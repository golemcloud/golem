# Additional Runtime APIs

### Generate an idempotency key

Golem provides a function to generate an idempotency key (a UUID) which can be passed to external systems to ensure that the same request is not processed multiple times.

It is guaranteed that this idempotency key will always be the same (per occurrence) even if the agent is restarted due to a crash.

To generate an idempotency key:

### Get agent metadata

It is possible to query **metadata** for Golem agents. This metadata is defined by the `AgentMetadata` interface:

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
    ```typescript
    /**
     * Metadata about an agent
     */
    export type AgentMetadata = {
      /** The agent ID, consists of the component ID, agent type and agent parameters */
      agentId: AgentId;
      /** Command line arguments seen by the agent */
      args: string[];
      /** Environment variables seen by the agent */
      env: [string, string][];
      /** Configuration variables seen by the agent */
      config: [string, string][];
      /** The current agent status */
      status: AgentStatus;
      /** The component revision the agent is running with */
      componentRevision: bigint;
      /** The agent's current retry count */
      retryCount: bigint;
      /** The environment the agent belongs to */
      environmentId: EnvironmentId;
    };
    ```

    There are two exported functions to query agent metadata:

    - `getSelfMetadata()` returns the metadata for the current agent
    - `getAgentMetadata(agentId: AgentId)` returns the metadata for a specific agent given by its `AgentId`, or `undefined` if it does not exist

    </Tabs.Tab>

### Enumerate agents

Agent enumeration is a feature of Golem available both through the public HTTP API and using the SDK.

<Callout type="warning">
    Enumerating agents of a component is a slow operation and should not be used as part of the application logic.
</Callout>

The following example demonstrates how to use the agent enumeration API:

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
```typescript
import {
  ComponentId,
  GetAgents,
  AgentAnyFilter,
  AgentMetadata,
  AgentStatusFilter,
} from "@golemcloud/golem-ts-sdk"

const filter: AgentAnyFilter = {
  filters: [
    {
      filters: [
        {
          tag: "status",
          val: {
            comparator: "equal",
            value: "idle",
          } satisfies AgentStatusFilter,
        },
      ],
    },
  ],
}

declare const componentId: ComponentId
const agents: AgentMetadata[] = []
const getter = new GetAgents(componentId, filter, true)

let batch: AgentMetadata[] | undefined
while ((batch = getter.getNext()) !== undefined) {
  agents.push(...batch)
}
```
    </Tabs.Tab>

    <Tabs.Tab>
```typescript
import { Stream } from "effect"
import { Agents } from "@golemcloud/effect-golem"

const enumerateAgents = (componentId: Agents.ComponentId) =>
  Agents.getAgents({ componentId, precise: true }).pipe(Stream.runCollect)
```
    </Tabs.Tab>

    <Tabs.Tab>
```rust
use golem_rust::{
    AgentAllFilter, AgentAnyFilter, AgentMetadata, AgentPropertyFilter, AgentStatus,
    AgentStatusFilter, ComponentId, FilterComparator, GetAgents,
};

let component_id: ComponentId = /* ... */;

let filter = AgentAnyFilter {
    filters: vec![AgentAllFilter {
        filters: vec![AgentPropertyFilter::Status(AgentStatusFilter {
            comparator: FilterComparator::Equal,
            value: AgentStatus::Idle,
        })],
    }],
};

    agents.extend(batch);
}
```
    </Tabs.Tab>

    <Tabs.Tab>
```scala

val filter: HostApi.AgentAnyFilter = HostApi.AgentAnyFilter(
  List(
    HostApi.AgentAllFilter(
      List(
        HostApi.AgentPropertyFilter.status(
          HostApi.AgentStatusFilter(HostApi.FilterComparator.Equal, HostApi.AgentStatus.Idle)
        )
      )
    )
  )
)

val componentId: HostApi.ComponentIdLiteral = ???
val handle = HostApi.getAgents(componentId, Some(filter), precise = true)

var agents: List[HostApi.AgentMetadata] = Nil
var batch = HostApi.nextAgentBatch(handle)

while (batch.isDefined) {
  agents = agents ++ batch.get
  batch = HostApi.nextAgentBatch(handle)
}
```
    </Tabs.Tab>

    <Tabs.Tab>

```moonbit

        @api.AgentPropertyFilter::Status(@api.AgentStatusFilter::{

        }),
      ],
    },

```
    </Tabs.Tab>

    <Tabs.Tab>
```go
import "github.com/golemcloud/golem/sdks/go/golem"

var componentID golem.UUID = /* ... */

var agents []golem.AgentMetadata
for md, err := range golem.GetAgents(componentID, golem.GetAgentsOptions{
	Filter:  golem.AgentStatusFilter(golem.FilterEqual, golem.AgentStatusIdle),
	Precise: true,
}) {
	if err != nil {
		return err
	}
	agents = append(agents, md)
}
```

`golem.GetAgents` fetches the pages as the loop advances. Filters are combined with their `And` and `Or` methods; `golem.MustGetAgents` is the variant panicking on a failing page.
    </Tabs.Tab>
</Tabs>

The `precise` parameter or option enables precise mode. In this mode, Golem calculates the latest metadata for each returned agent; otherwise, it uses only the last cached values.

### Oplog search and query
Golem provides APIs to read and search an agent's persisted oplog.

Each oplog entry describes a recorded operation or lifecycle event. You can either read all entries or supply a search expression to return only matching entries.

Results are paginated. Read successive batches until the query returns no more entries. For CLI usage, see [Observability](/v1.6/develop/observability).

### Invocation context

Golem associates an **invocation context** with each invocation, which contains various information depending on how the exported function was called. This context gets inherited when making further invocations via agent-to-agent communication, and it is also possible to define custom **spans** and associate custom **attributes** to it.

The spans are not automatically sent to any tracing system but they can be reconstructed from the oplog, for example using **oplog processor plugins**, to provide real-time tracing information.

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
The TypeScript SDK does not currently expose invocation-context inspection or custom span creation through its public API. See [Observability](/v1.6/develop/observability) for logs and trace export.

</Tabs.Tab>

    <Tabs.Tab>
Effect TypeScript installs a Golem-backed tracer automatically. Use `Tracing.currentContext` for an immutable snapshot of the host context and normal Effect spans for custom work:

```typescript
import { Effect } from "effect"
import { Tracing } from "@golemcloud/effect-golem"

const operation = Effect.gen(function* () {
  const context = yield* Tracing.currentContext
  return context.traceId
}).pipe(Effect.withSpan("my-operation"))
```

Use `Tracing.traceContextHeaders`, `withForwardedHeaders`, and `withInvocationParent` for explicit propagation.

These Effects are intended to run inside an Effect agent handler, where the dispatcher installs the required host services.
</Tabs.Tab>

    <Tabs.Tab>
To get the current invocation context, use the `current_context` host function, imported from `golem_rust::bindings::golem::api::context`:

The `InvocationContext` resource exposes various methods for querying attributes of the invocation context:

| method | description |
| ------ | ----------- |
| `trace_id` | Returns the trace ID associated with the context, coming from either an external trace header or generated at the edge of Golem |
| `span_id` | Returns the span ID associated with the context |
| `parent` | Returns the parent invocation context, if any |
| `get_attribute` | Gets an attribute from the current span by key, or searches the full parent chain when `inherited` is `true` |
| `get_attributes` | Gets all attributes from the current span, or the merged attribute set from the full parent chain when `inherited` is `true` |
| `get_attribute_chain` | Gets all values of a given attribute from the current and parent contexts |
| `get_attribute_chains` | Get all attributes and their previous values |
| `trace_context_headers` | Gets the W3C Trace Context headers associated with the current invocation context |

Custom attributes can only be set on **custom spans**. First start a new span using `start_span`

```rust

 * Starts a new `span` with the given name, as a child of the current invocation context
```

| method | description |
| ------ | ----------- |

| `set_attribute` | Sets an attribute on the span |
| `set_attributes` | Sets multiple attributes on the span |
| `finish` | Ends the current span |

If `finish` is not explicitly called on the span, it is going to be finished when the `Span` value is dropped.

### Key-value store

Although Golem agents can store their state completely in their own memory, they can also store key-value pairs in Golem-managed storage.

This can be useful if state needs to be shared between different agents or if the size of this state is too large to be stored in memory. Storage is shared across agents and components within the same environment.

Use a small value for shared settings. A missing key is distinct from a storage failure; do not turn every failure into a default value. The examples below write and read one greeting. Separate calls do not form a transaction.

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
Use `openBucket` to open a bucket. Opening is asynchronous; the bucket's methods are synchronous and work with `Uint8Array` values. A missing key returns `undefined`; storage failures throw.

```typescript
import { openBucket } from "@golemcloud/golem-ts-sdk"

async function greeting(): Promise<Uint8Array | undefined> {
  const bucket = await openBucket("shared")
  bucket.set("greeting", new TextEncoder().encode("hello"))
  return bucket.get("greeting")
}
```

        | Method | Result |
        | ------ | ------ |
        | `get(key)` | The stored bytes, or `undefined` when the key does not exist |
        | `set(key, value)` | Creates or replaces a value |
        | `delete(key)` | Deletes a key, if present |
        | `exists(key)` | Whether a key exists |
        | `getMany(keys)` | One value or `undefined` for each key |
        | `setMany(entries)` | Stores several key-value pairs |
        | `deleteMany(keys)` | Deletes several keys |
        | `keys()` | All keys in the bucket |

        `bucket.forSchema(schema)` provides the same operations with schema-validated values instead of bytes.
    </Tabs.Tab>

    <Tabs.Tab>
Use `KeyValue.openBucket` inside `Effect.scoped` to open a bucket. Its methods return effects with byte values. A missing key returns `Option.none()`; storage failures use the error channel.

        ```typescript
        import { Effect } from "effect"
        import { KeyValue } from "@golemcloud/effect-golem"

        const program = Effect.scoped(
          Effect.gen(function* () {
            const bucket = yield* KeyValue.openBucket("shared")
            yield* bucket.set("greeting", new TextEncoder().encode("hello"))

          }),
        )
        ```

| API | Result |
| --- | ------ |

Use `Bucket::open_bucket` to open a bucket. The `eventual` module provides single-key operations; `eventual_batch` provides batch operations. Storage failures return `Err`; a missing key returns `Ok(None)`.

```rust
use golem_rust::bindings::wasi::keyvalue::{
    eventual,
    types::{Bucket, OutgoingValue},
};

fn greeting() -> Result<Option<Vec<u8>>, String> {
    let bucket = Bucket::open_bucket("shared")
        .map_err(|e| format!("{e:?}"))?;
    let outgoing = OutgoingValue::new_outgoing_value();
    outgoing.outgoing_value_write_body_sync(b"hello")
        .map_err(|e| format!("{e:?}"))?;
    eventual::set(&bucket, "greeting", &outgoing)
        .map_err(|e| format!("{e:?}"))?;
    let value = eventual::get(&bucket, "greeting")
        .map_err(|e| format!("{e:?}"))?;
    value.map(|value| {
        value.incoming_value_consume_sync().map_err(|e| format!("{e:?}"))
    }).transpose()
}
```

| --------- | --- |

| Read / write several keys | `eventual_batch::get_many` / `eventual_batch::set_many` |
| Delete several keys / list keys | `eventual_batch::delete_many` / `eventual_batch::keys` |

```moonbit
fn greeting() -> Result[FixedArray[Byte]?, @wasiKeyvalueError.Error_] {
  let bucket = match @types.Bucket::open_bucket("shared") {
    Ok(bucket) => bucket
    Err(error) => return Err(error)
  }
  defer bucket.drop()
  let outgoing = @types.OutgoingValue::new_outgoing_value()
  defer outgoing.drop()
  match outgoing.outgoing_value_write_body_sync([104, 101, 108, 108, 111]) {
    Ok(_) => ()
    Err(error) => return Err(error)
  }
  match @eventual.set(bucket, "greeting", outgoing) {
    Ok(_) => ()
    Err(error) => return Err(error)
  }
  match @eventual.get(bucket, "greeting") {
    Err(error) => Err(error)
    Ok(None) => Ok(None)
    Ok(Some(value)) => {
      defer value.drop()
      value.incoming_value_consume_sync().map(bytes => Some(bytes))
    }
  }
```

### Blob store

The blob store provides a way to store and retrieve large binary data. This can be useful for storing large files or other binary data that is too large to be stored in the agent's memory. Storage is shared across agents and components within the same environment.

Read a bounded range instead of loading a large object into memory. Each example below opens the existing `documents` container and reads the first five bytes of `hello.txt`, which must contain at least five bytes. Start and end offsets are inclusive. Releasing a handle does not delete the stored data.

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
Use `getContainer` to open an existing container or `getOrCreateContainer` to open or create one. Container operations return promises with `Uint8Array` values; storage failures reject the promise.

```typescript
import { getContainer } from "@golemcloud/golem-ts-sdk"

async function documentPrefix(): Promise<Uint8Array> {
  const container = await getContainer("documents")
  return await container.getData("hello.txt", 0n, 4n)
}
```

        | Method | Result |
        | ------ | ------ |
        | `getData(name, start?, end?)` | Object bytes as a `Uint8Array`; optional offsets are inclusive |
        | `writeData(name, bytes)` | Creates or replaces an object from a `Uint8Array` |
        | `listObjects()` | An array of object names |
        | `has(name)` | Whether an object exists |
        | `delete(name)` | Deletes an object, if present |
        | `deleteMany(names)` | Deletes several objects |
        | `objectInfo(name)` | Object metadata, including its size |
        | `info()` | Container metadata |
        | `clear()` | Deletes all objects in the container |

The SDK also exports `containerExists`, `deleteContainer`, `copyObject`, and `moveObject`. Copy and move locations have the shape `{ container: string, object: string }`. Use `container.forSchema(schema)` for schema-validated object values instead of bytes.
    </Tabs.Tab>
