# High-level transactions

The SDKs provide saga helpers for workflows that need **compensation actions** after a domain failure.

Each host call remains durable on its own. A saga registers compensations for successful steps and runs them in reverse order when a later step fails. Compensation is a new external action, not deletion of the earlier effect.

Sagas do not provide atomicity or isolation. Earlier calls and their compensations remain in history, and other tasks can observe effects before compensation runs.

The SDK provides support for two different types of transactions:

- **fallible transactions** compensate failures and report the outcome
- **infallible transactions** compensate failures and ask the host policy before appending a new attempt

### Fallible transactions

A workflow can use compensations to counter earlier successful operations when a later operation fails. For example, a compensation can request a refund after a charge. It does not erase the charge or hide it from other tasks, and the compensation itself can fail.

A **fallible transaction** deals with domain errors. Successful steps register compensations. Propagating a domain error out of the transaction body triggers these compensations in reverse order; handling the error inside the body does not automatically trigger rollback. The failing step has no registered compensation. TypeScript, Rust, Scala and Go stop at the first compensation error and report partial rollback. Effect's `withFallibleCompensation` continues the remaining compensations and reports the first compensation error.

### Infallible transactions

After each failed, fully compensated infallible attempt, the SDK resolves a host policy with verb
`saga`, noun the agent URN, and `attempt`/`error-kind` properties. The host's `next-retry-delay`
uses the existing evaluator and an opaque binary continuation. SDKs carry that state unchanged
and use durable clocks and timers. No matching policy selects the agent default. Unbounded
policies are rejected rather than silently capped. Count/time/never exhaustion returns a typed
guest failure; selector/evaluator errors retain the original failure too.

New attempts append calls and retain failed attempts and compensations. Bounds keep attempts
finite; they do not rewind history. Reconstruction repairs an incomplete call at its original
`Start`, without discarding sibling history. TS, Effect, Scala and Go compensate caught failures
in reverse order. Fallible helpers propagate the original exception/panic only after complete
rollback; partial rollback retains both failures. Effect external cancellation stops retries and
preserves original and compensation evidence in Cause; self-interruption is policy-retryable.
Rust WASM panic aborts without compensation. An uncatchable deterministic guest trap permanently
fails the invocation; generic infrastructure retry handling is unchanged. MoonBit exposes the
retry API but has no saga helper.

### Operations

Both transaction types require the definition of **operations**.

It is defined with the following interface:

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
        ```typescript
        /**
        * Represents a compensable step of the transaction.
        *
        * Implement this interface and use it within a saga block.
        * Compensable steps can also be constructed with `compensable`.
        */
        export interface Compensable<In, Out, Err> {
        /**
         * The action to execute.
         * @param input - The input to the operation.
         * @returns A promise resolving to the result of the operation.
         */
        execute(input: In): Promise<Result<Out, Err>>
        /**
         * Compensation to perform in case of failure.
         * Compensations should not throw errors.
         * @param input - The input to the operation.
         * @param result - The result of the operation.
         * @returns A promise resolving to the result of the compensation.
         */
        compensate(input: In, result: Out): Promise<Result<void, Err>>
    }
        ```

        There are two ways to define a compensable step:

        1. Implement the `Compensable` interface manually
        2. Use the `compensable` function to create one from a pair of closures

        ```typescript
        export function compensable<In, Out, Err>(
            execute: (input: In) => Promise<Result<Out, Err>>,
            compensate: (input: In, result: Out) => Promise<Result<void, Err>>,
        ): Compensable<In, Out, Err>
        ```

    </Tabs.Tab>

    <Tabs.Tab>
        `Saga.operation` creates a reusable Effect step. The compensation receives the input, successful output, and failure cause, and must have an infallible (`never`) error channel:

        ```typescript
        import { Effect } from "effect"
        import { Saga } from "@golemcloud/effect-golem"

        const op = Saga.operation({
          execute: (idx: number) => Effect.succeed(`id-${idx}`),
          compensate: (idx, id, _cause) =>
            Effect.log(`reverting ${id}, ${idx}`),
        })
        ```

        Use `Saga.withFallibleCompensation` instead when a compensation itself can fail.
    </Tabs.Tab>

    <Tabs.Tab>

      ```rust

      /// Represents a compensable step of the transaction.
      ///
      /// Implement this trait and use it within a `transaction` block.
      /// Operations can also be constructed from closures using `operation`.
      pub trait Operation: Clone {
          type In: Clone;
          type Out: Clone;
          type Err: Clone;

          /// Executes the operation which may fail with a domain error
          async fn execute(&self, input: Self::In) -> Result<Self::Out, Self::Err>;

          /// Executes a compensation action for the operation.
          async fn compensate(&self, input: Self::In, result: Self::Out) -> Result<(), Self::Err>;
      }


      ```

        There are two ways to define an operation:

        1. Implement the `Operation` interface manually
        2. Use the `operation` function to create an operation from a pair of closures

        ```rust
     /// Constructs an `Operation` from two closures: one for executing the operation,
     /// and one for rolling it back. The rollback operation always sees the input and
     /// the output of the operation.
     ///
     /// This operation can run the compensation in both fallible and infallible transactions.
     pub fn operation<In: Clone, Out: Clone, Err: Clone>(
         execute_fn: impl Fn(In) -> Pin<Box<dyn Future<Output = Result<Out, Err>>>> + 'static,
         compensate_fn: impl Fn(In, Out) -> Pin<Box<dyn Future<Output = Result<(), Err>>>> + 'static,
     ) -> impl Operation<In = In, Out = Out, Err = Err> {
         FnOperation {
             execute_fn: Rc::new(execute_fn),
             compensate_fn: Rc::new(compensate_fn),
         }
     }
        ```

### Executing operations

The defined operations can be executed in _fallible_ or _infallible_ mode:

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
    ```typescript
    import { compensable, fallibleSaga, infallibleSaga, Result } from "@golemcloud/golem-ts-sdk"

    // example operation with compensation
    const op = compensable<number, string, string>(
      async (idx) => {
        // the operation / side effect
        return Result.ok("id-" + idx)
      },
      async (idx, id) => {
        // compensation
        console.log(`reverting ${id}, ${idx}`)
        return Result.ok(undefined)
      }
    )

    // With fallibleSaga, errors are propagated using Result.
    const resultFallible = await fallibleSaga(async tx => {
      const firstId = await tx.execute(op, 1)
      if (firstId.isErr()) return firstId

      const secondId = await tx.execute(op, 2)
      if (secondId.isErr()) return secondId

      return Result.ok([firstId.val, secondId.val])
    })

    const resultInfallible = await infallibleSaga(async tx => {
      const firstId = await tx.execute(op, 1)
      const secondId = await tx.execute(op, 2)
      return [firstId, secondId]
    })
    ```

    import golem.Transactions

    import scala.concurrent.Future
    import scala.scalajs.concurrent.JSExecutionContext.Implicits.queue

    val op = Transactions.operation[Int, String, String](
      idx => Future.successful(Right(s"id-$idx"))
    )(
      (idx, id) => {
        println(s"reverting $id, $idx")
        Future.successful(Right(()))
      }
    )

    val resultFallible: Future[Either[Transactions.TransactionFailure[String], (String, String)]] =
      Transactions.fallibleTransaction[(String, String), String] { tx =>
        tx.execute(op, 1).flatMap {
          case Right(firstId) =>
            tx.execute(op, 2).map(_.map(secondId => (firstId, secondId)))
          case Left(error) =>
            Future.successful(Left(error))
        }
      }

    val resultInfallible: Future[Either[Transactions.TransactionFailure[Any], (String, String)]] =
      Transactions.infallibleTransaction { tx =>
        for {
          firstId <- tx.execute(op, 1)
          secondId <- tx.execute(op, 2)
        } yield (firstId, secondId)
      }
    // Handle Left outcomes for exhaustion, policy error or partial rollback.

    The function below uses `OrderOutcome` from the previous example. The callbacks are application code, not SDK exports. Implement them with durable HTTP or RPC host calls. Each callback must return `Err` only when it knows that the requested effect did not occur; reconcile ambiguous remote outcomes before returning. Confirmation must not return `Err` after it commits the order.

    ```moonbit
    ///|
    async fn place_order(
      order_id : String,
      reserve_stock : async (String) -> Result[String, String],
      charge_payment : async (String) -> Result[String, String],
      confirm_order : async (String) -> Result[Unit, String],
      refund_payment : async (String) -> Result[Unit, String],
      release_stock : async (String) -> Result[Unit, String],
    ) -> OrderOutcome {
      let reservation_id = match reserve_stock(order_id) {
        Ok(id) => id
        Err(error) => return Failed(error, [])
      }
      let mut payment_id : String? = None
      let original_error = match charge_payment(order_id) {
        Err(error) => error
        Ok(id) => {
          payment_id = Some(id)
          match confirm_order(order_id) {
            Ok(_) => return Confirmed
            Err(error) => error
          }
        }
      }
      let rollback_errors : Array[(String, String)] = []
      if payment_id is Some(id) {
        match refund_payment(id) {
          Ok(_) => ()
          Err(error) => rollback_errors.push(("refund payment", error))
        }
      }
      // Attempt stock release even if the refund failed.
      match release_stock(reservation_id) {
        Ok(_) => ()
        Err(error) => rollback_errors.push(("release stock", error))
      }
      Failed(original_error, rollback_errors)
    }
    ```

    This workflow handles returned domain errors. Raised errors propagate to the caller; they do not trigger this rollback path. It does not retry operations or failed compensations automatically. The caller must handle partial rollback explicitly, for example by recording the order for reconciliation instead of reporting that rollback completed.

    Keep execute and compensation calls duplicate-safe, with stable application idempotency keys such as the order ID and an operation name. Ordinary local callbacks are not durable by themselves. Golem records supported host calls and replays their results during recovery; a crash reconstructs the recorded prefix and repairs eligible incomplete calls. It does not undo external effects or make a remote service idempotent.
    </Tabs.Tab>

    ```go
    import (
        "fmt"

        "github.com/golemcloud/golem/sdks/go/golem"
        "github.com/golemcloud/golem/sdks/go/golem/transaction"
    )

    // example operation with compensation
    var op = transaction.NewOperation(
        func(idx int32) golem.Result[string, string] {
            // the operation / side effect
            return golem.Ok[string, string](fmt.Sprintf("id-%d", idx))
        },
        func(idx int32, id string) golem.Result[golem.Unit, string] {
            // compensation
            fmt.Printf("reverting %s, %d\n", id, idx)
            return golem.Ok[golem.Unit, string](golem.Unit{})
        },
    )

    type Pair = golem.Tuple2[string, string]

    // With Fallible, errors are propagated using golem.Result.
    resultFallible := transaction.Fallible(func(tx *transaction.Tx[string]) golem.Result[Pair, string] {
        firstID := tx.Step(op, 1)
        if firstID.IsErr() {
            return golem.Err[Pair, string](firstID.Err())
        }
        secondID := tx.Step(op, 2)
        if secondID.IsErr() {
            return golem.Err[Pair, string](secondID.Err())
        }
        return golem.Ok[Pair, string](Pair{A: firstID.Ok(), B: secondID.Ok()})
    })

    // With Infallible, a returned error compensates and retries the whole transaction.
    resultInfallible := transaction.Infallible(func(tx *transaction.Tx[string]) golem.Result[Pair, string] {
        firstID := tx.Step(op, 1)
        if firstID.IsErr() {
            return golem.Err[Pair, string](firstID.Err())
        }
        secondID := tx.Step(op, 2)
        if secondID.IsErr() {
            return golem.Err[Pair, string](secondID.Err())
        }
        return golem.Ok[Pair, string](Pair{A: firstID.Ok(), B: secondID.Ok()})
    })
    ```
