# Read-only agent methods

Golem lets agent authors mark individual agent methods as **read-only**. A read-only method is one you promise
performs only a pure read of the agent's state, and Golem caches its result, so read-heavy methods can be served
without waiting behind slow writes — and without even loading the agent when a cached value is available.

This page explains what the runtime actually enforces (and, just as importantly, what it does **not**), how the
cache policies work, and how to use the marker from each SDK.

## What "read-only" means

A read-only method must be a **pure function of the agent's already-loaded state and the method inputs**: it must
not change anything, and its result must depend only on its inputs and the current state. That is the contract you
are promising.

Golem enforces only part of this contract:

| Allowed | Not allowed — runtime-enforced | Not allowed — author's responsibility |
|---|---|---|
| Reading the agent's state fields | Writing through durable host APIs (key-value and blob storage, external databases, promises, agent management, …) | Mutating in-memory state (assigning to a field) |
| Computation over the method inputs | Outgoing HTTP requests | Reading the clock / current time |
| Returning derived/aggregated values | RPC calls to other agents | Randomness |
| | | Reading environment variables |
| | | Remote / blob reads |
| | | Creating, writing, or deleting the agent's own files |

Operations in the middle column trap **before the call runs or any change is persisted**. The invocation
fails with a typed `ReadOnlyViolation` that identifies the agent method and offending host function.
Golem does not detect the operations in the right column: in-memory writes are not host calls, and
filesystem permissions do not enforce the read-only contract. These operations can make cached
results incorrect, so you must avoid them yourself. If you need them, use a regular (non-read-only) method.

In exchange for honoring this contract, Golem provides:

| Guarantee | What it means |
|---|---|
| Cached result | The result is cached per `(method, normalized input, caller)` on the worker. |
| Queue & loading bypass | A cache hit returns immediately — it never acquires the agent's invocation queue and never loads an evicted agent. |

<Callout type="info">
  A cache **hit** writes nothing to the oplog and does not load the agent. A cache **miss** (or a `no-cache`
  method) still runs through the queue and writes the usual `AgentInvocationStarted` / `AgentInvocationFinished`
  markers — needed for oplog visibility, fuel accounting, and idempotency-key result lookup.
</Callout>

## Cache policies

The cache policy is part of the read-only marker — non-read-only methods cannot carry one.

| Policy | Behavior |
|---|---|
| `until-write` (default) | The cached result is valid until the next non-read-only invocation on the same agent invalidates it. |
| `ttl(d)` | The cached result expires after duration `d`, even if no write happened in the meantime. |
| `no-cache` | The method runs every time without caching; the read-only contract still applies. |

After a successful non-read-only invocation commits its completion marker, Golem invalidates cached read-only
results for that agent. While a mutation is queued or running, readers can still receive the previous cached
value. Updating or reverting the agent also invalidates its cache; evicting and reloading only the WebAssembly
instance does not. `ttl(d)` entries additionally expire by time. `no-cache` never inserts into the cache.

## Caching per caller

The executor keys each cached result on the method, the normalized input and the full caller of the invocation:
the original and immediate principals and the tokens (see
[Make Secure HTTP APIs](/next/invoke/making-custom-apis/authentication)). Two calls by the same signed-in user can
share an entry. Calls by two different users never share one. All anonymous calls share one entry. There is no
option for this, and a method needs no extra parameter for it.

So a read-only method can return a view that depends on who is calling. It reads its caller from the invocation
context, like any other handler. In this example, each user sees only their own notes:

    <Tabs.Tab>
        ```typescript
        import { z } from "zod"
        import { defineAgent, method, PrincipalRef } from "@golemcloud/golem-ts-sdk"

        type Note = { author: PrincipalRef; text: string }

        export const NotesAgent = defineAgent({
          name: "NotesAgent",
          id: { name: z.string() },
          methods: {
            addNote: method({ input: { text: z.string() }, returns: z.void() }),
            // Read-only: cached per caller, so each caller gets their own entry
            myNotes: method({ input: {}, returns: z.array(z.string()), readOnly: true }),
          },
        })

        export const NotesAgentImpl = NotesAgent.implement({
          init: () => ({ notes: [] as Note[] }),
          methods: {
            addNote({ text }, ctx) {
              const author = ctx.caller.original.ref
              if (author === undefined) {
                throw new Error("Sign in to add a note")
              }
              this.notes.push({ author, text })
            },
            myNotes(_input, ctx) {
              const me = ctx.caller.original
              return this.notes.filter(note => me.equals(note.author)).map(note => note.text)
            },
          },
        })
        ```

              Effect.gen(function* () {
                const { caller } = yield* InvocationContext.InvocationContext
                const author = caller.original.ref
                if (author === undefined) {
                  return yield* Effect.die(new Error("Sign in to add a note"))
                }
                yield* Ref.update(notes, (all) => [...all, { author, text }])
              }),
            myNotes: () =>
              Effect.gen(function* () {
                const { caller } = yield* InvocationContext.InvocationContext
                const all = yield* Ref.get(notes)
                return all.filter((note) => caller.original.equals(note.author)).map((note) => note.text)
              }),
          }),
        })

The stored author is a `PrincipalRef`: an issuer and a subject, which grant nothing by themselves. This cache key does
not decide HTTP cache visibility; see [HTTP cache headers](#http-cache-headers) for the response privacy rules.

## Read-only and ephemeral are mutually exclusive

Read-only methods read the agent's **shared, already-loaded state**. [Ephemeral agents](/next/develop/durability)
get a fresh instance per invocation and have no shared state to read from, so a read-only method on an ephemeral
agent has no meaning. The host rejects this combination when the agent registers its types; individual SDKs may
also reject it earlier.

## Marking a method read-only

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
        Mark a method read-only by setting `readOnly: true` on its `method(...)` spec:

        ```typescript
        import { z } from "zod"
        import { defineAgent, method } from "@golemcloud/golem-ts-sdk"

        export const CounterAgent = defineAgent({
          name: "CounterAgent",
          id: { name: z.string() },
          methods: {
            // Non-read-only: writes shared state
            increment: method({ input: {}, returns: z.number() }),
            // Read-only: pure read over already-loaded state
            getCount: method({ input: {}, returns: z.number(), readOnly: true }),
          },
        })

        export const CounterAgentImpl = CounterAgent.implement({
          init: () => ({ count: 0 }),
          methods: {
            increment() {
              this.count += 1
              return this.count
            },
            getCount() {
              return this.count
            },
          },
        })
        ```

        `readOnly: true` uses the default `until-write` cache policy. For finer control, pass an object instead of
        the boolean:

        ```typescript
        methods: {
          // TTL cache: the result expires 30s after it is computed
          recentSummary: method({
            input: {},
            returns: Summary,
            readOnly: { cache: { ttlNanos: 30_000_000_000n } },
          }),
          // Never cached, but still side-effect-free
          pureCompute: method({
            input: { x: z.number(), y: z.number() },
            returns: z.number(),
            readOnly: { cache: "no-cache" },
          }),
        }
        ```

## Performance contract

- **Queue bypass.** On a cache hit the result is returned without acquiring the agent's invocation queue, so a
  read-only call is *not* blocked behind a slow write that is currently being processed.
- **Agent-loading bypass.** The cache lives on the worker independently of whether the WebAssembly instance is
  loaded. A cache hit is served even when the agent is currently evicted — no instance loading happens.
- **Automatic RPC fast path.** The cache lookup sits at the single invocation entry point shared by the public API
  and agent-to-agent RPC, so an RPC into a read-only method on the same node hits the cache too.
- **Concurrent coalescing.** Many identical first-time reads coalesce into a single execution; the rest wait for
  and share that one result.

## HTTP cache headers

When a read-only method is mapped to an HTTP `GET` or `HEAD` endpoint (see
[Exposing agents over HTTP](/next/develop/http)), Golem emits cache-friendly response headers derived from the
cache policy. For anonymous requests, successful responses use these defaults:

| Cache policy | Response headers |
|---|---|
| `no-cache` | `Cache-Control: no-store` |
| `until-write` | `Cache-Control: public, no-cache` + an opaque `ETag` |
| `ttl(d)` | `Cache-Control: public, max-age=<d>` + an opaque `ETag` |

The TTL is floored to whole seconds. Authenticated requests receive `Cache-Control: private, no-cache`,
even for TTL methods. An existing `no-store` policy remains stronger: authenticated responses then receive
`Cache-Control: private, no-store`. Responses that issue credentials also receive `private, no-store`.
Response headers cannot weaken these privacy requirements.

HTTP privacy depends on whether the request is authenticated. The executor's cache key always holds the caller
(see [Caching per caller](#caching-per-caller)). Anonymous responses vary on `Authorization`, `Cookie` and
`Golem-Token`. Golem also merges header-bound method parameters and any configured session header into `Vary`.

A request that repeats the returned ETag in `If-None-Match` is revalidated cheaply. The ETag holds a digest of the
caller, so it never revalidates another caller's request. If it still matches the caller, the agent's current
agent-instance fingerprint and oplog position, Golem returns `304 Not Modified` without executing
the agent method or loading its WebAssembly instance.

A response a CDN or browser sees for an anonymous request to an `until-write` method therefore looks like:

```http
HTTP/1.1 200 OK
Cache-Control: public, no-cache
Vary: Authorization, Cookie, Golem-Token
ETag: "<opaque-etag>"
Content-Type: application/json

{"count":7}
```

and a later conditional request short-circuits to:

```http
GET /counter-1/count HTTP/1.1
If-None-Match: "<opaque-etag>"

HTTP/1.1 304 Not Modified
Cache-Control: public, no-cache
Vary: Authorization, Cookie, Golem-Token
ETag: "<opaque-etag>"
```

<Callout type="warning">
  Read-only methods bound to non-`GET`/`HEAD` verbs are allowed, but they do not get read-only freshness or ETag
  headers. The authentication and credential privacy requirements still apply. Deployment validation emits a
  warning for each such binding.
</Callout>
