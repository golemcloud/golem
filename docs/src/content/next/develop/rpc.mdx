# Agent to Agent communication

See [Agent communication](/next/concepts/communication) for an overview of how agents call, wait for, and stream to each other.

## Code-first approach

When defining an _agent_ in code, this automatically defines a client interface for calling remote agents as well. This way an agent of an agent type can create other agents and invoke methods on them. The target agent can be of any agent type available for the caller agent in code.

The simplest way to achieve this is to keep all the agent types that need to call each other in the same _component_. For agents in different components, use a [generated guest bridge](#calling-an-agent-in-another-component) instead of importing the target's implementation.

## Creating a client

The first step of calling a remote agent is creating a _client_ for it by specifying which agent type it is and identifying the agent by providing values for its constructor parameters. If the agent identified by the parameters has not been existing yet, it is going to be created and its constructor is executed remotely. If it has been already created, the client just points to it and no action is taken until an _agent method_ is called using it.

The examples below return illustrative weather data for the selected location.
The caller returns the remote method's result, rather than fetching a real weather service.

In the following example, we have two agents defined; a weather agent with a constructor parameter identifying a location, and another example agent creating and calling this weather agent.

        ```typescript
        import { z } from 'zod';
        import { defineAgent, method } from '@golemcloud/golem-ts-sdk';

        export const WeatherAgent = defineAgent({
            name: 'WeatherAgent',
            id: { location: z.string() },
            methods: {
                currentWeather: method({
                    input: {},
                    returns: z.string(),
                    description: "Gets the current weather",
                }),
            },
        });

        export const WeatherAgentImpl = WeatherAgent.implement({
            init: ({ id }) => ({ location: id.location }),
            methods: {
                currentWeather() {
                    return `${this.location}: sunny, 18°C`;
                },
            },
        });

        export const ExampleAgent = defineAgent({
            name: 'ExampleAgent',
            id: {},
            methods: {
                run: method({ input: {}, returns: z.string() }),
            },
        });

        export const ExampleAgentImpl = ExampleAgent.implement({
            init: () => ({}),
            methods: {
                async run() {
                    const weatherInLondon = WeatherAgent.client.get({ location: "London" });
                    return await weatherInLondon.currentWeather({});
                },
            },
        });
        ```

        Here `weatherInLondon` is the client for calling a remote `WeatherAgent`, obtained from `WeatherAgent.client` with the target agent's id record - it exposes the agent methods, such as `currentWeather` as its own methods.

```typescript
import { Effect, Schema } from "effect"
import { defineAgent, method } from "@golemcloud/effect-golem"

export const WeatherAgent = defineAgent({
  name: "WeatherAgent",
  mode: "durable",
  id: { location: Schema.String },
  methods: {
    currentWeather: method({ input: {}, success: Schema.String }),
  },
})

export const WeatherAgentImpl = WeatherAgent.implement({
  init: ({ location }) => Effect.succeed(location),
  methods: (location) => ({
    currentWeather: () => Effect.succeed(`${location}: sunny, 18°C`),
  }),
})

export const ExampleAgent = defineAgent({
  name: "ExampleAgent",
  mode: "durable",
  id: {},
  methods: { run: method({ input: {}, success: Schema.String }) },
}).implement({
  init: () => Effect.void,
  methods: () => ({
    run: () => Effect.scoped(Effect.gen(function* () {
      const weatherInLondon = yield* WeatherAgent.client.get({ location: "London" })
      return yield* weatherInLondon.currentWeather({})
    })).pipe(Effect.orDie),
  }),
})
```

The scope releases the client after the call. The client exposes each agent method as an Effect-returning function. This example uses `Effect.orDie` to trap on RPC failures; alternatively, handle them or map them to an error declared by the calling method.

}

```go filename="agents/weather/impl/impl.go"
package impl

import (
	"myapp/agents/weather"

	"github.com/golemcloud/golem/sdks/go/golem"
)

type state struct{ location string }

var agent = weather.Agent.Implement(func(id weather.ID) *state { return &state{location: id.Location} })

func init() {
	agent.Handle(weather.CurrentWeather, func(ctx *golem.Context[state], _ golem.Unit) string {
		return ctx.State.location + ": sunny, 18°C"
	})
}
```

```go filename="agents/example/example.go"
package example

import "github.com/golemcloud/golem/sdks/go/golem"

type ID struct{}

var Agent = golem.DefineAgent[ID](golem.Spec{Name: "ExampleAgent"})

var Run = Agent.Method[golem.Unit, string]("run")
```

```go filename="agents/example/impl/impl.go"
package impl

import (
	"myapp/agents/example"
	"myapp/agents/weather"

	"github.com/golemcloud/golem/sdks/go/golem"
)

type state struct{}

var agent = example.Agent.Implement(func(example.ID) *state { return &state{} })

func init() {
	agent.Handle(example.Run, func(ctx *golem.Context[state], _ golem.Unit) string {
		weatherInLondon := weather.Agent.Get(weather.ID{Location: "London"})
		return weather.CurrentWeather.MustCall(weatherInLondon, golem.Unit{})
	})
}
```

Here `weatherInLondon` is a `golem.Client[weather.ID]` for calling a remote `WeatherAgent`, obtained from the target's definition with its `ID`. The caller imports only the definition package, never the target's `impl` package. The method descriptors of the definition, such as `weather.CurrentWeather`, are called with this client.

## Calling an agent in another component

Declare the target agent in the caller component's `dependencies.agents`. During `golem build`, Golem builds the provider, discovers its agent schema, generates a typed guest client in the caller's language, and then builds the caller. The provider and caller can use different SDKs. You do not need to share or duplicate the agent definition.

The dependency names the provider component and agent type. When creating a client, pass the constructor values that identify the target agent, not a component ID or server address.

The examples below assume that the application already contains a component named `example:weather`. It exports the durable `WeatherAgent` from the earlier example: its constructor takes a location, and its weather method returns a string. Merge the caller configuration into the existing `golem.yaml`, then add the generated client to the caller's build as shown in your SDK's tab. Paths assume the default `golem-temp` directory at the application root.

### Phantom agents
Calling `get` **gets or creates** a durable agent identified by its constructor parameters. Durable agent types have a default instance and can have arbitrary **phantom** instances distinguished by an additional **phantom ID** UUID. Ephemeral clients expose only phantom factories.

When using **agent IDs** (for example in APIs or the CLI), phantom IDs are appended to the agent ID in square brackets:
- Primary instance of `WeatherAgent` with parameter `London`:
  - `WeatherAgent("London")`
- A phantom instance of the same agent: 
  - `WeatherAgent("London")[43d9d7ab-e1d7-47e2-a213-d635eaa317a2]`

Phantom agents are created through Agent-to-Agent communication or [forking](/next/develop/forking). To create a new phantom agent via RPC, use the alternative client constructor method:

## Dynamic RPC

When the target agent type or method is selected at runtime, use [Agent reflection](/next/develop/reflection). It supports discovering agent schemas, addressing phantom agents, and invoking methods dynamically without importing the target's definition or generating a guest bridge.

## Triggering execution of an agent method
It is possible to trigger the remote execution of an agent method without awaiting it. This is useful for spawning background tasks, for example.

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
    To trigger an agent method and return immediately, use the `trigger` method exposed on each remote method in the client:

    ```typescript
    const remoteAgent = BackgroundTaskAgent.client.get({ jobId: backgroundJobId });
    remoteAgent.runTask.trigger({ message: "hello", count: 1234 });
    ```
    </Tabs.Tab>

    <Tabs.Tab>
    Each remote method exposes a typed `trigger` Effect:

    ```typescript
    const remoteAgent = yield* BackgroundTaskAgent.client.get({ jobId: backgroundJobId })
    yield* remoteAgent.runTask.trigger({ message: "hello", count: 1234 })
    ```
    </Tabs.Tab>

    <Tabs.Tab>
    To trigger an agent method and return immediately, use the `trigger_` variant exposed on the generated client.
    Example: If there is a `run_task`, its trigger variant is `trigger_run_task`:

    ```rust
    let remote_agent = BackgroundTaskAgentClient::get(background_job_id);
    remote_agent.trigger_run_task("hello".to_string(), 1234);
    ```
    </Tabs.Tab>

    <Tabs.Tab>
    To trigger an agent method and return immediately, use the `trigger` method exposed on each remote method in the generated client:

    ```scala
    val remoteAgent = BackgroundTaskAgentClient.get(backgroundJobId)
    remoteAgent.runTask.trigger("hello", 1234)
    ```
    </Tabs.Tab>

    <Tabs.Tab>
    To trigger an agent method and return immediately, use the `trigger_` variant exposed on the generated client.
    Example: If there is a `run_task`, its trigger variant is `trigger_run_task`:

    ```moonbit
    let remote_agent = BackgroundTaskAgentClient::get(background_job_id)
    defer remote_agent.drop()
    remote_agent.trigger_run_task("hello", 1234)
    ```
    </Tabs.Tab>

    <Tabs.Tab>
    To trigger an agent method and return immediately, use the `Trigger` method of the method descriptor. It returns the `golem.InvocationID` of the enqueued invocation, and an error if the invocation could not be enqueued (`MustTrigger` panics instead):

    ```go
    remoteAgent := backgroundtask.Agent.Get(backgroundtask.ID{JobID: backgroundJobID})
    backgroundtask.RunTask.MustTrigger(remoteAgent, backgroundtask.RunTaskIn{Message: "hello", Count: 1234})
    ```
    </Tabs.Tab>

### Scheduling an agent method
An advanced case of triggering the execution of an agent method is to **schedule it** to be executed at a later time.

<Tabs items={["TypeScript", "Effect TypeScript", "Rust", "Scala", "MoonBit", "Go"]} storageKey="nextra-tabs-language-sdk">
    <Tabs.Tab>
    Similar to `.trigger`, there is a `.schedule` method as well on each remote agent method in the client:

    ```typescript
    const remoteAgent = BackgroundTaskAgent.client.get({ jobId: backgroundJobId });
    remoteAgent.runTask.schedule({ seconds: 60n, nanoseconds: 0 }, { message: "hello", count: 1234 });
    ```

    Here the first parameter is a `Datetime` object, with seconds and nanoseconds fields representing the UNIX Epoch time when the method should be executed. In TypeScript, `seconds` is a `bigint`. The rest of the parameters are the same as for the original method.

    </Tabs.Tab>

    <Tabs.Tab>
    Pass an absolute time as a `Datetime`, JavaScript `Date`, Effect `DateTime`, or numeric Unix-epoch milliseconds:

    ```typescript
    const remoteAgent = yield* BackgroundTaskAgent.client.get({ jobId: backgroundJobId })
    yield* remoteAgent.runTask.schedule(new Date(Date.now() + 10 * 60 * 1000), {
      message: "hello",
      count: 1234,
    })
    ```
    </Tabs.Tab>

      <Tabs.Tab>
        Similar to `trigger`, there is a `schedule` variant for each remote agent method in the client.
        Example: If `run_task` is a method, its schedule variant is `schedule_run_task`:

        ```rust
        use golem_rust::ScheduledTime;

        let mut remote_agent = BackgroundTaskAgentClient::get(background_job_id);

        remote_agent.schedule_run_task(
          "hello".to_string(),
          1234,
          ScheduledTime {
            seconds: 60,
            nanoseconds: 0,
          },
        ).expect("failed to schedule background task");
        ```

        Here the last parameter is a `ScheduledTime`, with seconds and nanoseconds fields representing the UNIX Epoch time when the method should be executed. The rest of the parameters are the same as for the original method.

     </Tabs.Tab>

     <Tabs.Tab>
        Similar to `trigger`, there is a `scheduleAt` method as well on each remote agent method in the generated client:

        ```scala
        val remoteAgent = BackgroundTaskAgentClient.get(backgroundJobId)
        remoteAgent.runTask.scheduleAt("hello", 1234, golem.Datetime.afterSeconds(60))
        ```

        Here the last parameter is a `Datetime` object representing when the method should be executed. The rest of the parameters are the same as for the original method.

     </Tabs.Tab>

     <Tabs.Tab>
        Similar to `trigger`, there is a `schedule_` variant for each remote agent method in the generated client.
        Example: If `run_task` is a method, its schedule variant is `schedule_run_task`:

        ```moonbit
        // In moon.pkg:
        // import { "golemcloud/golem_sdk/interface/wasi/clocks/system-clock" @systemClock }

        let remote_agent = BackgroundTaskAgentClient::get(background_job_id)
        defer remote_agent.drop()
        remote_agent.schedule_run_task(
          @systemClock.Instant::{ seconds: 60, nanoseconds: 0 },
          "hello",
          1234,
        )
        ```

        Here the first parameter is a system-clock `Instant`, with `seconds` and `nanoseconds` fields representing the UNIX Epoch time when the method should be executed. The rest of the parameters are the same as for the original method.

     </Tabs.Tab>


     <Tabs.Tab>
        Similar to `Trigger`, there is a `Schedule` method on each method descriptor:

        ```go
        remoteAgent := backgroundtask.Agent.Get(backgroundtask.ID{JobID: backgroundJobID})
        scheduled := backgroundtask.RunTask.MustSchedule(
          remoteAgent,
          time.Now().Add(60*time.Second),
          backgroundtask.RunTaskIn{Message: "hello", Count: 1234},
        )
        ```

        Here the second parameter is a `time.Time` representing when the method should be executed, and the last one is the method's input. The returned `*golem.ScheduledInvocation` can be canceled with `scheduled.Cancel()` until the invocation starts. `Schedule` returns the same value with an error instead of panicking.

     </Tabs.Tab>
</Tabs>
