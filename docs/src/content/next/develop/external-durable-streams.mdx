# Consuming External Durable Streams

Agents can read and append to any protocol-compatible Durable Streams URL through `golem:agent/durable-streams@2.0.0`. The SDK creates a finite host reader or writer resource; the host owns HTTP, SSE framing, authorization, status validation, and durable result recording.

Resource construction records the immutable URL, mode or producer identity, timeout, and pinned secret identity **without making a network call**. Each finite read or append call is durably recorded. During replay, Golem returns the recorded outcome and makes no external request.

## SDK examples

<Tabs items={["Rust", "TypeScript", "Effect", "Scala", "MoonBit"]} storageKey="external-durable-streams-language">
<Tabs.Tab>
```rust
use golem_rust::durable_streams::{
    DurableStreamWriter, ExternalDurableStream, ReadOptions, WriteOptions,
};

async fn copy(source: String, target: String) -> Result<(), Box<dyn std::error::Error>> {
    let mut input = ExternalDurableStream::<u64>::json(source, ReadOptions::default());
    let mut output = DurableStreamWriter::new(
        target,
        "application/json",
        WriteOptions::default(),
    )?;

    while let Some(value) = input.next().await? {
        output.append_json(&[value], false).await?;
    }
    output.close().await?;
    Ok(())
}
```

Use `ExternalDurableStream::bytes` and `append_bytes` for bytes. With the agentic feature, `into_agent_stream()` transfers a reader into a method result, nested stream, or RPC argument.

```typescript
import { Effect, Schema, Stream } from "effect";
import { DurableStreams } from "@golemcloud/effect-golem";

const copy = Effect.gen(function* () {
  const input = DurableStreams.readJson(Schema.Number, {
    url: "https://streams.example/source",
    offset: "-1",
    live: "sse",
  });
  const output = yield* DurableStreams.makeJsonWriter(Schema.Number, {
    url: "https://streams.example/target",
    producerId: "copy-agent",
  });

  yield* input.pipe(Stream.runForEach(value => output.append([value])));
  yield* output.close;
}).pipe(Effect.scoped);
```

Use `readBytes` and `makeByteWriter` for bytes. Readers are native Effect `Stream` values, and writers remain valid while their acquisition scope is open.

```scala
import golem.streams.*
import scala.concurrent.{ExecutionContext, Future}

val input = DurableStreams.json[Long](
  "https://streams.example/source",
  DurableStreamReadOptions(
    checkpoint = DurableStreamCheckpoint("-1"),
    liveTransport = DurableStreamTransport.Sse
  )
)
val output = DurableStreams.jsonWriter[Long](
  "https://streams.example/target",
  producer = DurableStreamProducer("copy-agent")
)

def copyAll()(using ExecutionContext): Future[Unit] =
  input.pull().flatMap {
    case Some(value) => output.append(Vector(value)).flatMap(_ => copyAll())
    case None        => output.close().map(_ => ())
  }
```

```moonbit
async fn copy_all(
  reader : @durable_streams.Reader[Int],
  writer : @durable_streams.Writer[Int],
) -> Unit {
  match reader.read() {
    Some(value) => {
      let _ = writer.append([value])
      copy_all(reader, writer)
    }
    None => { let _ = writer.close() }
  }
}

}
```

## Checkpoints and transports

Readers default to offset `-1` and always begin with catch-up. `now` resolves once to a concrete offset. After reaching the tail, select long-poll or SSE; Scala and MoonBit also expose repeated catch-up. Offset and cursor are separate opaque server tokens.

One complete batch is buffered and drained before its checkpoint advances. A final payload is delivered before EOF. Empty, up-to-date, or `204` responses are not EOF. Byte readers yield individual bytes; append and HTTP batch boundaries are not application boundaries. JSON codecs handle each complete logical value, so an array-valued message remains one item.

Forwarded native-stream failures fail the producer/session rather than becoming clean EOF. Use result-valued stream items for recoverable application errors. Missing (`404`), gone (`410`), authorization, decode, protocol, fencing, sequence, and payload-size failures are errors, not EOF.

The worker executor's `[durable_stream].external_batch_max_size` limits each complete external read or append payload and defaults to 8 MiB. An oversized read does not advance its checkpoint; retrying it with the same limit cannot make progress. See [Operating Durable Streams](/next/operate/durable_streams#executor-configuration).

## Authentication

Pass a secret **capability**, not plaintext. The host pins its identity when the resource is constructed, checks reveal and network permissions, resolves the value only for a live request, and sends a string secret as a Bearer token. Do not reveal it in guest code or place credentials in the URL.

- Rust uses the raw secret handle from a configured `Secret<String>`.
- TypeScript accepts its public config `Secret<string>` wrapper and borrows a fresh raw capability internally without calling `get()`.
- Effect yields the `borrow` Effect from a `Schema.Redacted(Schema.String)` config field and passes the resulting opaque capability as `auth`.
- Scala accepts `auth = Some(config.token)` for a declared `golem.config.Secret[String]`.
- MoonBit constructors borrow `auth : @types.Secret?` directly.

HTTPS is required except for localhost/literal-loopback development. Redirects and URL userinfo are rejected.

## Retries and suspension

Only timeout, transport, `429`, and unavailable failures retry automatically. SDKs use bounded exponential backoff, durable timers, and at least the server's `Retry-After`. Protocol and conflict errors do not retry. An active finite HTTP attempt remains resident until completion or its deadline; idle and backoff timers may suspend the agent.

Replay reconstructs checkpoints, buffered-item indexes, retry state, producer state, and pending writes from recorded outcomes. Do not wrap these calls in another durability or atomic scope, and do not disable idempotence for external writes unless fail-closed recovery is acceptable.

## Pending writes and exactly-once effects

Each writer serializes requests and retains one immutable pending append: encoded payload, close flag, producer ID, epoch, and sequence. Sequence advances only after an exact acknowledgement. If a request fails or is cancelled, call `retryPending` / `retry_pending` with no new data. Never replace uncertain data, steal an epoch, or renumber automatically.

Close-only consumes a sequence. An acknowledgement may omit `Stream-Next-Offset`; the optional receipt still acknowledges the tuple. A response cannot reliably label a duplicate because `204` can also mean a fresh ordinary or close-only append.

Exactly-once external effects require the peer to atomically persist data and producer deduplication state and retain that state. A Golem agent fork copies the same external URL, checkpoint, producer ID, epoch, and pending data. It does **not** create an external Durable Streams fork or an independent producer; divergent branches can collide on a tuple and surface `ProducerDiverged`. Create a new producer identity deliberately when branches must write independently, after resolving any uncertain append.
