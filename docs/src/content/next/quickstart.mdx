# Quickstart

In this quickstart you run Golem on your machine, deploy a small counter agent, and call it four times. Between calls you crash the agent and restart the whole server. The counter still returns 1, 2, 3, 4, because Golem keeps the agent's state without any database or save call in your code.

It takes about ten minutes once the prerequisites are installed.

## Before you start

### Install the `golem` binary

The `golem` binary contains the command-line interface and a complete Golem server that runs locally. Download the binary for your platform:

| Platform | Binary |
| -------- | ------ |
| macOS ARM64 | <ArtifactLink artifact="golem" platform="mac-arm64" version={NEXT_RELEASE_VERSION} /> |
| macOS x86_64 | <ArtifactLink artifact="golem" platform="mac-x64" version={NEXT_RELEASE_VERSION} /> |
| Linux ARM64 | <ArtifactLink artifact="golem" platform="linux-arm64" version={NEXT_RELEASE_VERSION} /> |
| Linux x86_64 | <ArtifactLink artifact="golem" platform="linux-x64" version={NEXT_RELEASE_VERSION} /> |
| Windows x86_64 | <ArtifactLink artifact="golem" platform="windows-x64" version={NEXT_RELEASE_VERSION} /> |

Rename the downloaded file to `golem`, make it executable (`chmod +x golem` on macOS and Linux), and move it to a directory on your `PATH`. Some systems block downloaded binaries until you allow them in the system settings. Check the installation:

```shell copy
golem --version
```

On Windows, use WSL (Windows Subsystem for Linux) and follow the Linux instructions. Native Windows binaries are available to try, but Windows is not fully supported and operation is not guaranteed.

A lighter `golem-cli` binary without the local server exists for working against a remote Golem deployment; see the [CLI reference](/next/cli).

### Install the toolchain for your language

`golem build` compiles agents with the language's own toolchain. TypeScript and Effect need **Node.js 24.11 or newer** and **npm 11.6.2 or newer**. For Rust, Scala, MoonBit, and Go, install the toolchain listed on the [Setup](/next/develop/setup) page.

## Start Golem locally

This walkthrough uses two terminals. **Terminal 1** runs the server; **Terminal 2** runs every other command.

In **Terminal 1**, from any directory:

```shell copy
golem server run
```

The first start downloads and provisions Golem's built-in plugins and tools, so it takes longer than later starts. Leave the server running.

The project also contains an `AGENTS.md` file and skill files with Golem-specific instructions for AI coding tools. `golem templates` lists every available template. Build the application and deploy it to the local server:

```shell copy
cd agent-examples
golem build
```

Keep Terminal 2 in the `agent-examples` directory for the remaining commands.

## Call the same agent twice

An agent is addressed by its agent type and its constructor parameters. `CounterAgent("my-counter")` names one agent; Golem creates it on the first call. In **Terminal 2**, from the `agent-examples` directory:

```shell copy
golem agent invoke 'CounterAgent("my-counter")' increment
golem agent invoke 'CounterAgent("my-counter")' increment
```

Each command ends with the method's result. The first call prints `1` and the second prints `2`. Excerpt of the second call's output (the label names the component's language):

```text
Invocation result in TypeScript syntax:
2
```

A different name, such as `CounterAgent("other")`, addresses a different agent with its own count starting at zero.

## Crash the agent

Simulate a crash, then call the agent again without redeploying:

```shell copy
golem agent simulate-crash 'CounterAgent("my-counter")'
golem agent invoke 'CounterAgent("my-counter")' increment
```

The invocation prints `3`. The crash discarded the agent's running instance and its memory. Golem started a fresh instance and rebuilt the agent's state from its oplog, the durable record of what the agent has done.

## Restart the server

In **Terminal 1**, stop the server with `Ctrl+C`, then start it again without `--clean`:

```shell copy
golem server run
```

`golem server run --clean` deletes all local server data, including every agent and oplog, and would reset the counter.

When the server is running again, call the agent from **Terminal 2**:

```shell copy
golem agent invoke 'CounterAgent("my-counter")' increment
```

The invocation prints `4`.

Optionally, in **Terminal 2**, inspect the agent's recorded invocations:

```shell copy
golem agent oplog 'CounterAgent("my-counter")'
```

## What the counter showed

| Property | What it shows |
| -------- | ------------- |
| Identity | `CounterAgent("my-counter")` reached the same agent on every call. Its type and constructor parameters are its address. |
| Ordinary state | The count is an ordinary field. The code has no save call or database write. |
| Recovery | After the crash, Golem rebuilt the state from the oplog, with no redeploy or manual restore. |
| Persistent local server data | The local server keeps components, agents, and oplogs in a `golem` directory under the platform's local data directory, so state survives a restart without `--clean`. |

## Recover a method in the middle of its work

The counter's state survived between calls. This second example shows Golem recovering a method that is still running. A `WorkflowAgent` starts a workflow, asks a `HumanAgent` for approval, and then waits inside its `start` method until the human decides. You restart the server while it waits, approve the workflow afterwards, and the method continues from the line where it stopped.

The example uses the `human-in-the-loop` template. The waiting is ordinary code: the method creates a promise, sends its ID to the human agent, and awaits it. In **Terminal 2**, leave the `agent-examples` directory, then follow the tab for your language. The constructor parameter `report-q3` names the workflow agent. The idempotency key `report-q3` identifies the waiting invocation, so you can ask for its result later.

`--trigger` returns before the workflow finishes registering its request. If the pending list is
empty, repeat the list command. Restart only after the list contains the workflow ID and
`golem agent get` reports `Suspended`. Always restart without `--clean`.

```typescript
// src/workflow-agent.ts (excerpt)
async start({ approver }) {
  const approvalPromiseId = createPromise();

  await HumanAgent.client.get({ username: approver }).requestApproval({
    workflowId: this.workflowId,
    promiseId: encodePromiseId(approvalPromiseId),
  });

  // The agent is suspended here until the promise is completed.
  const decision = new TextDecoder().decode(await awaitPromise(approvalPromiseId));

  return decision === "approved"
    ? `Workflow ${this.workflowId} was approved`
    : `Workflow ${this.workflowId} was rejected`;
},
```

```typescript
// src/workflow-agent.ts (excerpt)
start: ({ approver }) =>
  Effect.gen(function* () {
    const promiseId = yield* Agents.Promises.create;
    const human = yield* HumanAgent.client.get({ username: approver });
    const requestId = yield* Schema.decodeEffect(Ids.PromiseId)(promiseId);
    yield* human.requestApproval({ workflowId, promiseId: requestId });
    const bytes = yield* Agents.Promises.await(promiseId);
    const decision = new TextDecoder().decode(bytes);
    return decision === "approved"
      ? `Workflow ${workflowId} was approved`
      : `Workflow ${workflowId} was rejected`;
  }).pipe(Effect.orDie, Effect.scoped),
```

```rust
// src/workflow_agent.rs (excerpt)
async fn start(&mut self, approver: String) -> String {
    let approval_promise_id = create_promise();

    let mut approver = HumanAgentClient::get(approver);
    approver
        .request_approval(self.id.clone(), approval_promise_id.clone())
        .await;

    // The agent is suspended here until the promise is completed.
    let result: Decision = await_promise_json(&approval_promise_id)
        .await
        .expect("Invalid promise payload");

    if result == Decision::Approved {
        format!("Workflow {} was approved ✅", self.id)
    } else {
        format!("Workflow {} was rejected ❌", self.id)
    }
}
```

```go
// agents/workflow/impl/impl.go (excerpt)
agent.Handle(workflow.Start, func(ctx *golem.Context[state], in workflow.StartIn) string {
	approval := golem.NewPromise[string]()

	approver := human.Agent.Get(human.ID{Username: in.Approver})
	human.RequestApproval.MustCall(approver, human.RequestApprovalIn{
		WorkflowID: ctx.State.workflowID,
		PromiseID:  approval.ID(),
	})

	// The agent is suspended here until the promise is completed.
	decision := approval.MustAwait()

	if decision == "approved" {
		return fmt.Sprintf("Workflow %s was approved", ctx.State.workflowID)
	}
	return fmt.Sprintf("Workflow %s was rejected", ctx.State.workflowID)
})
```

The approval completed the promise that `start` was waiting on, and the method continued on a server that did not exist when it started. Repeating the invocation with the same idempotency key returned the recorded result instead of starting a second workflow, because a method invocation executes exactly once per idempotency key.
