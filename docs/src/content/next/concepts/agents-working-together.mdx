# Agents working together

Agents coordinate through typed method calls, durable waits, and streams. Golem records and delivers each of them, so an application needs no message queue, scheduler, or callback router between its agents.

## Await, trigger, or schedule a method call

Defining an agent type also defines a typed client for it. A caller gets a client from the target's address, the agent type plus its constructor parameters, and calls its methods. Golem creates the target agent on its first invocation if it does not exist yet. Every non-streaming remote method can be called in three ways:

| Call | What the caller does |
|---|---|
| Await | Waits for the result; a failure surfaces as an error |
| Trigger | Enqueues the invocation and continues immediately |
| Schedule | Enqueues the invocation for a given time and receives a cancellation token |

The following excerpt shows three alternatives for requesting a review: await its result, trigger it, or schedule it.

```typescript
// Excerpt: alternative calls from ReportAgent to ReviewerAgent
const reviewer = ReviewerAgent.client.get({ team: "finance" });
const draft = "Quarterly report draft";

const review = await reviewer.review({ draft });
reviewer.review.trigger({ draft });

const inOneHour = {
  seconds: BigInt(Math.floor(Date.now() / 1000) + 3600),
  nanoseconds: 0,
};
const token = reviewer.review.schedule(inOneHour, { draft });
token.cancel();
```

Agent-to-agent calls execute exactly once. Golem records the call in the caller's oplog, and every retry or replay carries the same idempotency key, so the target runs it once; [Durable by default](/next/concepts/durable-by-default) explains the mechanism. A scheduled call is stored durably until it runs or is cancelled. A recurring task is a method that schedules its own next run.

Each agent handles one invocation at a time, so two agents that await each other deadlock; trigger one of the calls instead.

## Call across components and languages

To call an agent type in another component, including one written in another language, declare it under `dependencies.agents` on the calling component in `golem.yaml`. `golem build` then generates a **guest bridge**: a typed client in the caller's language, produced from the target's schema rather than its source code, so a TypeScript agent calls a Rust agent with TypeScript types. Guest bridge calls are agent-to-agent calls with the same guarantees.

Programs outside Golem, such as a Node.js web server, use an **external bridge**: a generated client library in the program's language.

| | Guest bridge | External bridge |
|---|---|---|
| Caller | An agent in another component | A program outside Golem |
| Declared in `golem.yaml` | `dependencies.agents` | `bridge.<language>.external.agents` |
| Transport | Agent-to-agent calls | REST API; a WebSocket session for streaming methods |
| Runtime setup | None | `configure(...)` with server, application, and environment |

## Wait for people and external events

A **promise** is a durable, one-time slot that an agent creates and awaits. Another agent can complete it with a payload through `completePromise`, and an external system through the REST API. A **webhook** is a promise with a one-time public URL; an HTTP `POST` to the URL completes the promise with the request body. Webhooks require an HTTP mount and an `httpApi` deployment. Each webhook URL completes one promise, so treat it as a secret.

```typescript
// Excerpt: ReportAgent waits for approval
const webhook = createWebhook();
await sendApprovalLink(webhook.getUrl()); // application function
const payload = await webhook; // the agent is suspended here
const event = payload.json();
```

An agent that is only waiting, for example on a promise, is suspended after a short idle threshold. Golem unloads it from memory, so it uses no compute while suspended. The wait lives in the oplog, not in a process, so it survives restarts and redeployments. When the promise completes, Golem rebuilds the agent from its oplog and the `await` returns. [Living with agents](/next/concepts/living-with-agents) covers what a suspended agent still costs.

Deadlines, reminders, and escalation are application logic built from these primitives, not built-in policies. For an approval with a deadline, the waiting agent can schedule a call on another agent that completes the same promise with a default decision; a promise completes only once, so the first completion decides. The `human-in-the-loop` template created by `golem new` shows the approval pattern end to end.

## Stream results and resume connections

Methods can accept and return streams of values or bytes, with back-pressure in both directions. Streaming methods are called with await only; trigger, schedule, and MCP export do not support them.

External bridges and `golem agent invoke` run streaming methods over a resumable WebSocket session, specified by the [Stream Session Public Protocol v1](/next/invoke/stream-session-public-protocol-v1). A dropped connection detaches the client without cancelling the invocation; the client resumes with its session token and last received positions, and the server replays the output that followed. Delivery across a reconnect is at least once, so consumers with external side effects should deduplicate items. Streaming TypeScript and Effect bridges run on Node.js only.

<Callout type="info">
  Bridge WebSocket sessions are separate from **Durable Streams**, the HTTP protocol Golem serves
  for streaming methods of HTTP-mounted agents. [Artifacts](/next/concepts/artifacts) covers
  Durable Streams.
</Callout>

## Discover collaborators at runtime

**Reflection** lets an agent list the agent types and tools visible to it, read their method schemas, including JSON Schema for a model's tool-calling API, and invoke them through discovered or fully dynamic clients. Golem still enforces visibility and authorization: reflection lists only what the caller may see, and every call is checked against the caller's [cards](/next/concepts/cards). See [Agent reflection](/next/develop/reflection).
