# Agents

An **agent** is a named, stateful instance of an agent type: a small, isolated computer with its own memory, files, history, and permissions. A user, an order, a conversation, or an LLM-driven assistant can each be an agent.

## A type defines agents; an address identifies one

An **agent type** defines state and methods. Agent types are compiled into a **component**, the unit you build and deploy; one component can define several agent types. As with an executable and its processes, Golem runs any number of agents of one type.

In TypeScript, `defineAgent` declares identity and methods, `implement` supplies handlers, and the object returned by `init` is the state, bound to `this`:

```typescript
// Excerpt: an agent type with a state-changing and a read-only method
export const CounterAgent = defineAgent({
  name: "CounterAgent",
  id: { name: z.string() },
  methods: {
    increment: method({ input: {}, returns: z.number() }),
    getCount: method({ input: {}, returns: z.number(), readOnly: true }),
  },
})

export const CounterAgentImpl = CounterAgent.implement({
  init: () => ({ count: 0 }),
  methods: {
    increment() {
      this.count += 1
      return this.count
    },
    getCount() {
      return this.count
    },
  },
})
```

An agent's address is its type plus its constructor parameters, the values in `id`. Within an environment, each set of values names exactly one agent. These are two different agents:

```text
CounterAgent("alice")
CounterAgent("bob")
```

Every call to `CounterAgent("alice")` reaches the same agent, whether it comes from the CLI, an HTTP endpoint, or another agent through `CounterAgent.client.get({ name: "alice" })`. An agent is **created on first use**. Deploying a component starts no agents, and existing agents stay on their revision until [updated](/next/develop/updating).

The address is not a security identity. Who may call an agent depends on caller authentication and principal checks; what the agent may do depends on its cards.

## An agent's memory, files, and authority

Each agent has its own:

- **WebAssembly instance and memory.** No other agent can read or write it.
- **Filesystem.** The agent cannot reach any file outside it.
- **Environment variables and configuration.**
- **Oplog**, its durable history.
- **Wallet of permission cards**, the only source of its authority. See [Authority: cards](/next/concepts/cards).

Ordinary state is durable: `this.count` survives crashes and restarts with no save call. See [Durable by default](/next/concepts/durable-by-default).

A new agent's filesystem may not be empty: files declared under `files` in `golem.yaml`, per component or per agent type, are seeded into every new agent, read-only or read-write. Agents written in TypeScript, Effect, and Rust can also use **embedded SQLite**, one database per agent, in memory or in a file.

Agents of one component share the compiled code, read-only. Other sharing is deliberate: an external PostgreSQL or MySQL database, or a key-value or blob bucket opened by name in the same environment, each checked against the agent's cards. Agents talk to each other only through typed methods, and one agent's failure does not affect another's health.

## Each agent runs one invocation at a time

Each agent processes one invocation at a time, in order, so agent code needs no locks. Other calls wait in the agent's queue.

For parallel work, use more agents: one per user, per document, or per task.

A **read-only method**, such as `getCount` above, is a fast path. Golem caches its result, by default until the next state-changing invocation, and a cache hit returns without waiting in the queue or loading the agent. Golem rejects outgoing HTTP, calls to other agents, and writes through its key-value, blob-storage, and external-database APIs. The read-only marker does not prevent changes to the agent's own files or fields, or clock reads, so keep these methods pure.

## Agent modes and phantom identities

| Kind | Chosen by | Behavior | Use it for |
|---|---|---|---|
| **Durable** (default) | The agent type | State, files, and in-progress execution survive invocations and failures. | Users, orders, conversations |
| **Ephemeral** | The agent type (`mode: "ephemeral"`) | A fresh instance per invocation; state is discarded and interrupted invocations are not recovered. | Stateless request handlers |
| **Phantom** | The caller, or HTTP mount configuration | Independent agents share constructor values and are told apart by a UUID. | Parallel runs of one job |

The mode belongs to each agent type in code, not to the component. A durable counter incremented three times returns 1, 2, 3. The same type marked ephemeral returns 1, 1, 1.

For a durable agent type, a caller creates a phantom with `newPhantom`, which returns a client for the new agent together with its UUID. Keep the UUID to reach the same agent again:

```typescript
// Excerpt: two phantom agents with the same constructor values
const { client, phantomId } = CounterAgent.client.newPhantom({ name: "alice" })
const second = CounterAgent.client.newPhantom({ name: "alice" }).client
const again = CounterAgent.client.getPhantom({ name: "alice" }, phantomId)
```

A phantom's address carries the UUID as a suffix, such as `CounterAgent("alice")[<uuid>]`.

## How agents are isolated

Each agent is a WebAssembly instance. Many agents share one host process; there is no container, virtual machine, or kernel per agent.

The boundary between agents is WebAssembly's memory isolation and its import surface. An instance reaches the outside world only through host imports, and the host checks every gated import against the agent's cards. Per-agent memory and disk limits apply, and CPU use is metered.

TypeScript and Effect agents, and Scala agents through Scala.js, run on a JavaScript runtime built on QuickJS and compiled to WebAssembly, not on Node.js. It provides `fetch`, web streams, and Node-compatible core modules, so most plain-JavaScript npm packages work; packages that need native addons do not. Rust, Go, and MoonBit agents compile directly to WebAssembly and use WASI.

<Callout type="info">
  No agent, in any language, can spawn host processes or load native libraries. A shell, Node,
  npm, or `tsc` comes to an agent as a WebAssembly tool. See [Tools](/next/concepts/tools).
</Callout>
