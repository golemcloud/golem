# Golem CLI Components

Golem components are WASM components deployed to Golem for execution.

Components are created with `golem new`, built with `golem build` and deployed with `golem deploy`. To inspect deployed components and manage their agents you can use the `golem component` command.

## Creating a new component

To create a new component in an existing application directory (previously created with `golem new`) use the `golem new` command with the `--component-name` option from within the application directory:

```shell copy
golem new --template <template-name> --component-name <component-name> .
```

To see all the available component templates, use the `golem templates` command.

This command only modifies the source code of the application, does not create anything on the server.

## Building a component

To build a component, use the `build` command in the following way:

```shell copy
golem build <component-name>
```

To build the whole application, use the `build` command without specifying a component name:

```shell copy
golem build
```

Both commands accept a `--preset <PRESET>` (`-P`) argument. The built-in templates define component presets, for example Rust components have a `debug` (default) and a `release` preset, the latter creating a more optimized version of the components. Presets can be fully customized by editing the _application manifest files_.

To deploy **all components** of an application, use:

```shell copy
golem deploy
```

## Component search

### Using component name and the current revision

If you want to get the currently deployed revision of the component using its name you can use the `component get` command. If the component name is omitted, the component is selected based on the current directory.

```shell copy
golem component get example:component
```

### Using component name and specific revision

To get a specific revision of a component, just pass the desired revision number as well:

```shell copy
golem component get example:component 2
```

### Getting component list

To list all the components deployed to the current environment you can use the `component list` command:

```shell copy
golem component list
```

<Callout>
  Commands working with deployed components and agents operate on the selected environment. Use
  `--environment <ENVIRONMENT>` (`-E`), `--local` (`-L`) or `--cloud` (`-C`) to select a different
  one.
</Callout>

## Updating component

To update a component just run the `golem deploy` command again.

If you want to trigger an update of all agents to the newly deployed revision you can use the `--update-agents <automatic|manual>` option.

It is possible to change the **component's type** (from durable to ephemeral, or from ephemeral to durable) when
updating the component by changing the manifest file.

## Updating agents

If you want to update all agents you can use `component update-agents` command.

This command gets all agents for the component that are not using the current revision and triggers an update for them one by one:

```shell copy
golem component update-agents example:component
```

The update request is enqueued and processed by the agents asynchronously. Use the `--await` flag to wait for the updates to finish, and `--update-mode manual` to use manual instead of automatic updates.

To update the agents of all components of the application, use `golem update-agents`.

<Callout type="warning">
  Note that automatic agent update is not guaranteed to succeed, if the updated component differs
  too much from the previous one.
</Callout>

## Redeploying agents

During the development of a Golem Component, it is often necessary to quickly rebuild the code, update the component and just restart all the test agents from scratch to test the changes.

This is different from updating the agents as they will loose their state, but it can speed up the feedback loop during development.

This workflow is supported by the `component redeploy-agents` command:

```shell copy
golem component redeploy-agents example:component
```

This command deletes all agents of the component and re-creates them with the same name, parameters and environment variables, using the current revision of the component.

To redeploy the agents of all components of the application, use `golem redeploy-agents`, or pass `--redeploy-agents` to `golem deploy`.
