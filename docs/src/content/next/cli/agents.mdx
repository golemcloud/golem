# Golem CLI Agents

Using `golem agent` command you can:

- Start and stop agent
- Interrupt and resume agents
- Invoke agent function
- Get agent stdout, stderr and logs
- Update agents
- Search agents, get metadata, etc.
- Revert a agent to a previous state

## Addressing agents

Every agent has an **agent ID**, a UUID that Golem issues when it creates the agent. An agent can also have a **key**: the agent type and its constructor parameters, such as `CounterAgent("my-counter")`. Only an agent created with a key (a keyed agent) can be found by its key. The agent commands accept these addresses:

- `CounterAgent("my-counter")` addresses the keyed agent of these constructor parameters.
- `CounterAgent[<AGENT_ID>]` and a bare `<AGENT_ID>` address an agent by its agent ID. An agent created without a key is reachable only this way.

Each form can be prefixed by the environment name (`<ENVIRONMENT>/`, `<APPLICATION>/<ENVIRONMENT>/` or `<ACCOUNT>/<APPLICATION>/<ENVIRONMENT>/`) if it is not inferrable from the current context.

## Create a new agent

Even though a keyed agent is automatically created on the first invocation by its key, it is possible to explicitly create an agent.
This allows specifying environment variables (`--env`) and configuration values (`--config`) for the agent.

Without `--keyed`, each `agent create` creates a new agent without a key, and prints its agent ID:

```shell copy
golem agent create 'CounterAgent("my-counter")' --env A=1 --env B=2
```

With `--keyed`, it creates the keyed agent of the constructor parameters, and fails when that agent already exists:

```shell copy
golem agent create --keyed 'CounterAgent("my-counter")' --env A=1 --env B=2
```

Use `--idempotency-key` (`-i`) to retry a create safely: a create retried with the same key returns the agent of the first create.

To get the keyed agent, and create it when it does not exist, use `agent upsert`:

```shell copy
golem agent upsert 'CounterAgent("my-counter")'
```

## Get agent metadata

You can get the agent metadata, including its agent ID, agent type, key and fingerprint, using any agent address:

```shell copy
golem agent get 'CounterAgent("my-counter")'
golem agent get 'staging/CounterAgent("my-counter")'
golem agent get 'CounterAgent[<AGENT_ID>]'
```

## Search agents

You can search for agents of some components or agent types using the `agent list` command with one or more `--filter` arguments.

For instance lets find idle agents with component revision older than 2 of the component `example:counter`:

```shell copy
golem agent list --filter "status = Idle" --filter "revision < 2" --component-name example:counter
```

The `key` property compares the key text of a keyed agent, such as `--filter 'key == CounterAgent("c1")'`; an agent without a key never matches it. The `id` property compares the agent ID.

<Callout type="warning">
  Enumerating agents is a slow operation and should only be used for debugging an administrative
  tasks.
</Callout>

## Invoking agent methods

The folowing section shows the basics of invoking agents through the CLI. See the [dedicated invocation with CLI page](/next/invoke/cli) for more details.

An invocation addressed by a key creates the keyed agent when it does not exist. An invocation addressed by an agent ID requires an existing agent. With `--expected-fingerprint <FINGERPRINT>`, the invocation fails and runs nothing unless the agent is the incarnation with this fingerprint (shown by `agent get`).

### Without waiting for result

You can invoke an agent function without waiting for function result using `agent invoke --trigger` command:

```shell copy
golem agent invoke --trigger 'CounterAgent("my-counter")' add 5
```

### Waiting for result

You can invoke an agent method and wait for result using `agent invoke` command:

```shell copy
golem agent invoke 'CounterAgent("my-counter")' value
```

```
Invocation result in TypeScript syntax:
5
```

The result is rendered using the source-language syntax of the agent.

### Using idempotency key

If you want to make sure function was called only once even if you called CLI multiple times (for instance due to retries on network errors) you can use the `--idempotency-key` parameter of the `invoke` command, both with and without `--trigger`.

You can use any string as idempotency key.

## Live streaming agent logs

You can connect to your running agent and stream its logs using the `agent stream` command:

```shell copy
golem agent stream 'CounterAgent("my-counter")'
```

By default, the `invoke` command streams the agent's output. Use the `--no-stream` option to disable this.

## Agent update

To update the agent to a specific component revision, use the `agent update` command:

```shell copy
golem agent update 'CounterAgent("my-counter")' auto 2
```

## Interrupt and resume agents

If you want to interrupt and later resume a long-running agent you can use `interrupt` and `resume` commands:

```shell copy
golem agent interrupt 'CounterAgent("my-counter")'
golem agent resume 'CounterAgent("my-counter")'
```

## Testing crash recovery

There is a special command to simulate a crash on an agent:

```shell copy
golem agent simulate-crash 'CounterAgent("my-counter")'
```

## Deleting agents

Idle agents are not actively consuming resources but they take storage as their state is persisted. An agent can be deleted using the `agent delete` command:

```shell copy
golem agent delete 'CounterAgent("my-counter")'
```

This command deletes agent state.

Please note that a next invocation to the same agent will recreate it with fresh state:

```shell
golem agent delete 'CounterAgent("my-counter")'
golem agent invoke 'CounterAgent("my-counter")' value
```

```
Invocation result in TypeScript syntax:
0
```

## Oplog query

It is possible to **query** an existing agent's oplog for debugging purposes. To get the **full oplog** of an agent, use the `agent oplog` command:

```shell copy
golem agent oplog 'CounterAgent("my-counter")'
```

With the optional `--from` parameter it is possible to only get oplog entries _after_ a certain oplog index:

```shell copy
golem agent oplog --from 100 'CounterAgent("my-counter")'
```

Oplog entries are indexed from 1, and the first entry is always a **create** entry that defines the initial state of the agent.

Each invocation entry shows its caller in three lines: `original caller:` is the principal that started the chain of calls, `immediate caller:` is the principal that made this call, and `tokens:` lists the tokens that the call carried. The verified claims of a signed-in user are hidden by default. Add `--show-claims` to show them, in a `claims:` line under the user. In the JSON, YAML and TOON formats, `claims` is an object. The server shows the claims only to a reader who may read the oplog. `--show-claims` cannot be combined with `--obfuscate`, because an obfuscated export never shows claims.

### Viewing the oplog in a browser

The oplog can be explored in an **interactive HTML viewer** instead of the terminal. The viewer groups the entries by invocation, merges each durable host call's **start** and **end** entries into one foldable row with its duration, nests the entries executed by tool entities under the tool invocation, and marks the regions skipped by a **jump** or a **revert**. It can filter by entry category, log level or index range, search the content of the entries, decode typed payloads, binary and snapshot data, and it shows per-invocation and per-type statistics.

The `--serve` parameter starts a local server that hosts the viewer and opens it in the default browser:

```shell copy
golem agent oplog 'CounterAgent("my-counter")' --serve
```

The served viewer loads the oplog **page by page** through the API, so it works for oplogs of any size. It can run a **Lucene query** on the server (the same syntax as `--query`, see below), load the context around a query hit, jump to any oplog index, and **follow** a running agent by polling for new entries. `--from` and `--query` select the initial position and query of the viewer. Use `--port` to choose the port and `--no-open` to skip opening the browser. The server runs until it is interrupted.

The `--html` parameter writes a **self-contained HTML file** instead, with every selected entry embedded in the page:

```shell copy
golem agent oplog 'CounterAgent("my-counter")' --html oplog.html --open
```

The generated file has no external dependencies, so it can be opened directly from disk or shared. `--open` opens it in the default browser. Because the page embeds all entries, it is meant for oplogs of moderate size; use `--from` or `--query` to narrow the selection, or `--serve` for large oplogs. The static viewer can also load a dump produced by `--format json` through its _Load JSON_ button.

### Exporting an obfuscated oplog

The `--obfuscate` parameter exports a report of the oplog that you can attach to a bug report. The CLI replaces the customer values with tokens on your machine:

```shell
golem agent oplog <agent> --obfuscate [--keep-scalars] [--keep-shape] [--keep-error-text] [--max-entry-bytes N] [--query Q | --from N] [--html FILE | --serve]
```

Write the report into a self-contained HTML file:

```shell copy
golem agent oplog 'CounterAgent("my-counter")' --obfuscate --html report.html
```

Or serve the viewer locally, with each page obfuscated:

```shell copy
golem agent oplog 'CounterAgent("my-counter")' --obfuscate --serve
```

In the structured formats, the export emits a sequence of documents in place of the `agent.oplog` documents: one `agent.oplog-export-header` document, one `agent.oplog-export-entry` document per oplog entry and one `agent.oplog-export-coverage` document. `--omit-payloads` cannot be used with `--obfuscate`. See [Sharing an Oplog](/next/debug/oplog-export) for what the report keeps, what it removes and what each `--keep-*` parameter leaks.

### Searching for oplog entries

Use `golem agent oplog --query` to return matching entries. `--query` cannot be combined with `--from`. The query language supports a subset of Lucene syntax:

- `search terms` requires both terms. Unquoted terms are case-insensitive substring matches.
- Uppercase `AND`, `OR`, and `NOT` combine or exclude matches. Each condition applies to the same entry, but can match a different value within it.
- Parentheses `()` group conditions. Use explicit operators and parentheses when mixing `AND` and `OR`: whitespace conjunction has lower precedence than `OR`, unlike explicit `AND`.
- `"quoted terms"` matches a case-sensitive substring, not a whole field value.
- `/regex/` uses [Rust regular expression syntax](https://docs.rs/regex/latest/regex/#syntax). Matches are case-sensitive unless the pattern enables another mode, such as `/(?i)timeout/`. Use `^` and `$` to match a complete value.
- `field:value` or `field=value` restricts a match to an exposed field path. `field:(first OR second)` groups conditions under that path.

Wildcards, range queries, and fuzzy matching are not supported. Use regular expressions rather than treating `*` or `?` in a bare term as wildcards.

The terms and fields are interpreted in the following way:

| Oplog entry                                                  | Matching queries                                                                                                                                              |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Create`                                                     | `create`                                                                                                                                                      |
| `Start` (durable host call started)                          | `start`, `imported-function`, match on the host function's name, match on request value(\*)                                                                   |
| `End` (durable host call finished)                           | `end`, match on response value(\*)                                                                                                                            |
| `Cancelled`                                                  | `cancelled`, match on partial value(\*)                                                                                                                       |
| `CompletionDiscarded` / `CompletionDelivered`                | `completion-discarded` / `completion-delivered`                                                                                                               |
| `AgentInvocationStarted`                                     | `agent-invocation-started`, `invoke`, and depending on the invocation kind: `agent-initialization`, `agent-method-invocation`, `external-tool`, `save-snapshot`, `load-snapshot`, `process-oplog-entries`; match on method or tool name, match on idempotency key, match on target revision (manual updates), match on the caller (see below) |
| `AgentInvocationFinished`                                    | `agent-invocation-finished`, `invoke`, match on consumed fuel                                                                                                 |
| `AgentInvocationSettled`                                     | `agent-invocation-settled`, match on invocation ID, match on consumed fuel |
| `PendingAgentInvocation`                                     | `pending-agent-invocation`, `invoke`, and the same invocation kind terms and matches as `AgentInvocationStarted` (pending external tool calls are not matched on idempotency key) |
| `Suspend`                                                    | `suspend`                                                                                                                                                     |
| `Error`                                                      | `error`, match on error message                                                                                                                               |
| `RecoverySucceeded`                                          | `recovery-succeeded`                                                                                                                                          |
| `Jump`                                                       | `jump`                                                                                                                                                        |
| `Interrupted`                                                | `interrupted`                                                                                                                                                 |
| `Exited`                                                     | `exited`                                                                                                                                                      |
| `PendingUpdate`                                              | `pending-update`, `update`, match on target revision                                                                                                          |
| `SuccessfulUpdate`                                           | `successful-update`, `update`, match on target revision                                                                                                       |
| `FailedUpdate`                                               | `failed-update`, `update`, match on target revision, match on error details                                                                                   |
| `GrowMemory`                                                 | `grow-memory`                                                                                                                                                 |
| `CreateResource`                                             | `create-resource`                                                                                                                                             |
| `DropResource`                                               | `drop-resource`                                                                                                                                               |
| `Log`                                                        | `log`, match on context, match on message                                                                                                                     |
| `Restart`                                                    | `restart`                                                                                                                                                     |
| `Resumed`                                                    | `resumed`                                                                                                                                                     |
| `ActivatePlugin`                                             | `activate-plugin`                                                                                                                                             |
| `DeactivatePlugin`                                           | `deactivate-plugin`                                                                                                                                           |
| `Revert`                                                     | `revert`                                                                                                                                                      |
| `CancelPendingInvocation`                                    | `cancel`, `cancel-invocation`, match on idempotency key                                                                                                       |
| `SetRetryPolicy` / `RemoveRetryPolicy`                       | `set-retry-policy` / `remove-retry-policy`                                                                                                                    |
| `Snapshot`                                                   | `snapshot`                                                                                                                                                    |
| `SnapshotConfirmed`                                          | `snapshot-confirmed` |
| `SpanClosed`                                                 | `span-closed` |
| `OplogProcessorCheckpoint`                                   | `oplog-processor-checkpoint`                                                                                                                                  |
| `BeginRemoteTransaction`, `CommittedRemoteTransaction`, etc. | `begin-remote-transaction`, `pre-commit-remote-transaction`, `pre-rollback-remote-transaction`, `committed-remote-transaction`, `rolled-back-remote-transaction` |
| Card entries                                                 | `card-installed`, `card-install-failed`, `card-derived`, `card-revoked`, `card-revoked-cascade`, `card-expired`, `card-event-queued`, `card-transfer-started`, `card-transferred`, `card-transfer-confirmed`; match on card ID or transfer ID |
| Tool attachment entries                                      | `tool-attachment-read`, `tool-attachment-control`; match on typed observation, attachment, or transition values(\*) |
| Stream entries                                               | `host-stream-frame`, `stream-registered`, `stream-items`, `stream-end`, `stream-cancel`, `stream-session`; match on typed frame payload or stream record values(\*) |

Unquoted terms match substrings: `start` also matches `agent-invocation-started`, and `snapshot` also matches `snapshot-confirmed`. These are searchable aliases, not exact entry-type filters; a term can also match a payload. Most entry kinds also match their name without dashes (for example `pendingupdate`), except `CancelPendingInvocation`.

Search does not inspect every displayed field. Displayed metadata such as timestamps, indices, and the host function's name does not automatically provide a field qualifier. Search a host function or agent method name with a bare term, not `function_name:...`. Invocation arguments and results are not searched by the invocation entries above.

The cases marked with **(\*)** support paths into typed values. For host calls, start with `request`, `response`, or `partial`, followed by record field names, for example `request.product-id:123`. Tuple elements use numeric segments, such as `request.0`; list elements share the list's path rather than adding an index. Field paths are case-insensitive and must match the complete exposed path. Tool attachment and stream records start at their own typed root, without a `request` prefix. A stream handle inside a typed value does not cause search to read the stream's contents.

Invocation entries also match on their caller. A bare term matches the kind (`user`, `account`, `agent`, `tool` or `anonymous`), the issuer and the subject of both roles, so `account` matches every call that an account made. The fields `caller`, `original`, `immediate`, `caller.original` and `caller.immediate` restrict the match, for example `original:bob` or `caller.immediate:agent`. Claims never match.

Span information belongs to host-call entries, not separate `StartSpan`, `FinishSpan`, or `SetSpanAttribute` entries:

| Entry | Searchable span paths |
| --- | --- |
| `Start` | `span-started.span-id`, `span-started.trace-id`, `span-started.parent-span-id`, `span-started.trace-states`, `span-started.links.trace-id`, `span-started.links.span-id`, `span-started.links.trace-states`, `span-started.attributes.<key>`; also `denial` when present. |
| `End` | `span-finished.span-id`, `span-attributes.span-id`, `span-attributes.attributes.<key>`. |
| `Cancelled` | `span-finished.span-id`. |

For example, `span-started.attributes.region:eu` searches a span attribute named `region`. Attribute keys containing dots cannot be addressed by a field qualifier; search their values with an unqualified term instead.

To find host-call requests with a `product-id` field whose complete value is `123` or `456`, use an anchored regular expression:

```shell
golem agent oplog 'CounterAgent("my-counter")' --query 'request.product-id:/^(123|456)$/'
```

## Reverting an agent

It is possible to revert an agent to its previous state. This can be useful if an agent got into a **failed** state to make it usable again, or to undo some accidental invocations or updates.

There are two possible ways to specify which state to revert to:

- **By index**: The index of the oplog entry to revert to. Use the **oplog query** command to check the agent's oplog and find the index of the desired state.
- **By undoing the last invocations**: The given number is the number of invocations to revert.

To revert to a given oplog, use the `agent revert` command:

```shell copy
golem agent revert 'CounterAgent("my-counter")' --last-oplog-index 42
```

To revert some of the last invocations, use the `--number-of-invocations` parameter instead:

```shell copy
golem agent revert 'CounterAgent("my-counter")' --number-of-invocations 3
```

## Inspecting and cancelling invocations

The `golem invocation` commands select an invocation by its agent and idempotency key, or by its invocation ID (`<agent ID>.<UUID>`), as listed by `golem invocation list`:

```shell copy
golem invocation get --agent 'CounterAgent("my-counter")' --idempotency-key my-key
golem invocation list --agent 'CounterAgent("my-counter")' --status pending --status scheduled
```

`invocation get` shows the state of the invocation (`scheduled`, `pending`, `running`, `waiting`, `retrying`, `interrupted`, `completed`, `background-failed`, `failed` or `cancelled`) and, once it finished, its result. A `background-failed` invocation recorded its result, then the agent failed during the background work that the method started: `invocation get` shows the result and the error, and `agent invoke` with the same idempotency key returns the result (addressed by agent ID, it also prints the error as a warning). When the key was used for more than one method of the agent, it shows the invocation of each method, and `--method` selects one. It exits with code 130 when an invocation it shows was cancelled. `invocation list` lists the invocations of an agent, newest change first, and prints a cursor for the next page.

A key is found only for the account that made the invocation, and invocations made through an HTTP route are not found by their key. An invocation ID is resolved in the current environment; select another one with `--environment`.

If an invocation is enqueued or scheduled for an agent, but it has not been started yet, it can be cancelled:

```shell copy
golem invocation cancel --agent 'CounterAgent("my-counter")' --idempotency-key my-key
```

A running invocation cannot be cancelled. An invocation that already finished keeps its result, also while the background work it started still runs.
