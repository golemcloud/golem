# Develop an application Golem

Developing an application on golem consists of two major steps:

- Writing one or more **Golem components** in one of the supported programming languages.
- Defining external HTTP endpoints

This page summarizes the workflow of developing an application on Golem, with links to more specific guides for each step.

## Creating an application
The primary tool for developing an application on Golem is the [Golem CLI](/next/cli).

To create a new application, use the `golem new` command, passing the application's directory and a template selecting the programming language of its first component (note: it is possible to add components using different languages later). Without `--template` the command asks for the template interactively, and `golem templates` lists all the available templates.

```shell copy
golem new --template ts my-app
```

## Writing the code
The application is just a project directory that can contain multiple components. To learn how to add a new component and implement it, check the specific guides in this chapter.

### Iterations
During development the whole application can be built using

```shell copy
golem build
```

and every component can be deployed using

```shell copy
golem deploy
```

This is going to create a new **revision** of each changed component. If there are agents created already, those are not going to be updated automatically to these new revisions, unless `golem deploy` is called with `--update-agents` (update the agents) or `--redeploy-agents` (delete and recreate the agents). Alternatively, `--reset` deletes the existing agents and the environment before deploying. Check the [agents page](/next/concepts/agents) for more information about updating agents.

## Defining APIs

Most applications require a public HTTP API (but this is not mandatory - you can always use Golem's invocation API to directly communicate with your Golem application).

### Guidelines

HTTP endpoints are defined **directly in the agent code**, by adding a mount point to the agent and exposing its methods as endpoints. Check the [defining custom APIs](/next/invoke/making-custom-apis) page as a starting point for learning how to define custom APIs.

### Iterations

The HTTP APIs are part of the application: to make them accessible, add an `httpApi` deployment section to the [application manifest](/next/app-manifest) mapping agents to domains per environment (see [Deployments](/next/invoke/making-custom-apis#deployments)). Every time the code or the manifest changes, deploy the application again:

```shell copy
golem deploy
```

The deployed HTTP APIs can be inspected with the `golem api deployment` commands.
