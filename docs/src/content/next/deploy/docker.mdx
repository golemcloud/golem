# Deploy using Docker

To try Golem with Docker, use a Docker Compose file from the [Golem Docker examples](https://github.com/golemcloud/golem/tree/main/docker-examples). You need [Docker](https://docs.docker.com/get-docker/) and [Docker Compose](https://docs.docker.com/compose/install/).

<Callout type="warning">
  These examples are for trying Golem on one machine. Their `.env` files contain tokens that are public, and they keep the blobs on a local volume. For a production deployment, see the [production checklist](/next/deploy/production-checklist) and the [fixed cluster with Docker Compose](/next/deploy/vm#fixed-cluster-with-docker-compose).
</Callout>

```bash filename="Terminal" copy
# Download the PostgreSQL example: the compose file and its .env file
curl -O https://raw.githubusercontent.com/golemcloud/golem/main/docker-examples/published-postgres/compose.yaml \
     -O https://raw.githubusercontent.com/golemcloud/golem/main/docker-examples/published-postgres/.env

# Start Golem with PostgreSQL and Redis as storage
docker compose -f compose.yaml up
```

You may need to modify it to suit your needs. The `golemservices/golem-router` image of the example is newer than the image version in `.env`; the comment in `compose.yaml` says how to build it. The [`distributed-etcd` example](https://github.com/golemcloud/golem/tree/main/docker-examples/distributed-etcd) runs the shard manager in etcd mode instead.

The Golem images run as uid and gid 65534. The example mounts its blob storage volume at `/data/blob_storage`, which belongs to that user in the images. If you replace a named volume with a bind mount, give the host directory to uid 65534 first. See [User and Permissions](/next/deploy#user-and-permissions).

### Accessing Golem APIs

The ports are set in the [`.env`](https://github.com/golemcloud/golem/blob/main/docker-examples/published-postgres/.env) file:

| Port | Serves |
| --- | --- |
| 9881 (`GOLEM_ROUTER_PORT`) | The router: the [Golem APIs](/next/rest-api) for the host `GOLEM_ROUTER_MANAGEMENT_HOST` (`localhost`), and the HTTP API and MCP deployments for every other host |
| 9006 (`WORKER_SERVICE_CUSTOM_REQUEST_PORT`) | HTTP API and MCP deployments, chosen by the request's host. See [HTTP gateway](/next/operate/architecture#the-gateway) |
| 9007 (`WORKER_SERVICE_MCP_PORT`) | MCP deployments only. See [MCP](/next/invoke/mcp) |

### Troubleshooting

- If a port is already in use on your machine, change it in the `.env` file.
- In some cases `docker compose` fails with the following error:

```bash
error getting credentials - err: exec: "docker-credential-desktop": executable file not found in $PATH, out: `
```

In this situation, rename `credsStore` to `credStore` in the `.docker/config.json` file.
