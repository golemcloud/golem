# Snapshots in Kotlin

Golem agents can implement snapshotting to support manual (snapshot-based) updates and snapshot-based recovery. The Kotlin SDK offers three mixins (all in package `cloud.golem`):

| Mixin | You provide | Use when |
|-------|-------------|----------|
| `Snapshotted<S>` | `override var state: S` | the default: KSP derives the byte codec from `S` at compile time |
| `CustomSnapshot` | `saveSnapshot(): ByteArray` / `loadSnapshot(bytes: ByteArray)` | you need your own encoding (compact binary, compatibility with older snapshots) |
| `MultipartSnapshotted` | `saveSnapshotParts(): MultipartSnapshot` / `loadSnapshotParts(snapshot: MultipartSnapshot)` | several named blobs, each with a content type |

`Snapshotted<S>` and `MultipartSnapshotted` can be mixed in together, which keeps a typed state beside your named blobs (see [Typed state beside the parts](#typed-state-beside-the-parts)). `CustomSnapshot` owns the whole payload and composes with neither; any other combination is a compile-time error. An ephemeral agent takes no snapshots (compile-time error if a cadence is set).

## When to Use Snapshotting

Snapshotting solves two distinct problems:

1. **Manual / snapshot-based component updates** — required when updating agents between incompatible component versions. The host calls the generated `save-snapshot` on the old component revision and `load-snapshot` on the new one.
2. **Fast recovery and oplog compaction** — for long-running agents whose oplog grows over time (heartbeats, polling loops, recurring tasks, agents with frequent state changes). Without snapshotting, every recovery replays the full oplog from the beginning, which becomes increasingly expensive. With periodic snapshotting (`every(N)` or `periodic(...)`), recovery starts from the latest snapshot and replays only the entries after it.

> **You cannot opt out of oplog writes for a durable agent.** If you are worried about oplog volume or replay cost, do *not* try to skip persistence — enable snapshot-based recovery here instead.

## Enabling Snapshotting

Two things are required, and they are independent:

1. **Mix in a snapshot interface** (`Snapshotted<S>`, `CustomSnapshot` or `MultipartSnapshotted`) — this provides the *state* that is saved and restored.
2. **Advertise a cadence** via `@Agent(snapshotting = ...)` — this tells the host *when* to snapshot.

The `save-snapshot`/`load-snapshot` guest exports are always generated, but a snapshot is only produced when a cadence is set. An agent that mixes in none of the interfaces produces an empty snapshot (a no-op on load).

### Snapshotting Modes

The `snapshotting` parameter accepts these values:

| Mode | Description |
|------|-------------|
| `"disabled"` | No snapshotting (default when omitted) |
| `"enabled"` | Enable snapshot support with the server's default policy. **The server default is `disabled`**, so this may have no effect. Use `"every(N)"` or `"periodic(…)"` to guarantee snapshotting is active. |
| `"every(N)"` | Snapshot every N successful function calls (use `"every(1)"` for every invocation). N must fit a u16 (`0..65535`). |
| `"periodic(<nanos>)"` | Snapshot at most once per interval given as an integer nanosecond count (e.g., `"periodic(30000000000)"` for 30 s). Duration strings such as `30s` are not accepted. |

## Typed Snapshotting with `Snapshotted<S>`

Bundle all mutable state into a WIT-mappable type (typically a `data class`), then mix `Snapshotted<S>` into your agent alongside `BaseAgent`:

**1. Define the state type** (must be WIT-mappable — a `data class`, `List`/`Map`/`Pair`/`Triple`, enum, sealed class, primitive, `Datetime`, or `Either`):

```kotlin
data class CounterState(val value: Int)
```

**2. Mix in `Snapshotted<S>` and enable a cadence:**

```kotlin
import cloud.golem.BaseAgent
import cloud.golem.Snapshotted
import cloud.golem.annotations.Agent
import cloud.golem.annotations.Endpoint

@Agent(mount = "/counters/{name}", snapshotting = "every(1)")
class CounterAgent(val name: String) : BaseAgent(), Snapshotted<CounterState> {
    override var state = CounterState(0)

    @Endpoint(post = "/increment")
    fun increment(): Int {
        state = CounterState(state.value + 1)
        return state.value
    }

    @Endpoint(get = "/value")
    fun getValue(): Int = state.value
}
```

KSP detects `Snapshotted<S>`, resolves `S`'s schema at compile time, and generates the snapshot codec that serializes/deserializes `state` — no manual serialization code. The state is wrapped in a principal-carrying envelope, so the caller identity captured at `initialize` is restored on load. On a manual update the SDK reconstructs the agent from its own agent-id (the constructor parameters) inside `load-snapshot`, so typed state survives both a revision bump and a worker restart.

### Requirements for `Snapshotted<S>`

- Declare `override var state: S` on the agent.
- `S` must be a WIT-mappable type. A non-mappable `S` is a **compile-time error**, never a silent empty snapshot.

There is no `stateSchema` field to declare (KSP derives it) and no `saveSnapshot`/`loadSnapshot` methods to write with this mixin.

## Custom bytes: `CustomSnapshot`

```kotlin
import cloud.golem.BaseAgent
import cloud.golem.CustomSnapshot
import cloud.golem.annotations.Agent
import cloud.golem.annotations.Endpoint

@Agent(mount = "/blobs/{name}", snapshotting = "every(10)")
class BlobAgent(val name: String) : BaseAgent(), CustomSnapshot {
    private var total = 0L

    @Endpoint(post = "/add")
    fun add(by: Long): Long { total += by; return total }

    override fun saveSnapshot(): ByteArray = total.toString().encodeToByteArray()
    override fun loadSnapshot(bytes: ByteArray) { total = bytes.decodeToString().toLong() }
}
```

## Named parts: `MultipartSnapshotted`

```kotlin
import cloud.golem.MultipartSnapshot
import cloud.golem.MultipartSnapshotted
import cloud.golem.SnapshotPart

override fun saveSnapshotParts() = MultipartSnapshot(mapOf(
    "meta" to SnapshotPart("v1".encodeToByteArray(), "text/plain"),
    "history" to SnapshotPart(historyBytes(), "application/octet-stream"),
))
override fun loadSnapshotParts(snapshot: MultipartSnapshot) {
    val meta = snapshot.requirePart("meta", "text/plain").decodeToString()
    restore(snapshot.requirePart("history"))
}
```

Part names match `[A-Za-z0-9_][A-Za-z0-9_.-]*`; content types are bare ASCII MIME types without parameters (lowercased). The multipart container format is private to the Kotlin SDK.

## Typed state beside the parts

Mix in `Snapshotted<S>` as well when some of the state is a plain Kotlin type and the rest is blobs. KSP derives the codec for `state` and puts it in a slot of its own in the same frame, so you encode only the parts:

```kotlin
import cloud.golem.MultipartSnapshot
import cloud.golem.MultipartSnapshotted
import cloud.golem.SnapshotPart
import cloud.golem.Snapshotted

data class LedgerState(val label: String, val total: Int)

@Agent(mount = "/ledger/{name}", snapshotting = "enabled")
class LedgerAgent(val name: String) : BaseAgent(), Snapshotted<LedgerState>, MultipartSnapshotted {
    override var state = LedgerState("fresh", 0)
    private var entries = mutableListOf<Int>()

    override fun saveSnapshotParts() = MultipartSnapshot(mapOf(
        "entries" to SnapshotPart(entries.joinToString("|").encodeToByteArray(), "text/plain"),
    ))

    override fun loadSnapshotParts(snapshot: MultipartSnapshot) {
        val values = snapshot.requirePart("entries", "text/plain").decodeToString()
        entries = if (values.isEmpty()) mutableListOf() else values.split("|").map { it.toInt() }.toMutableList()
    }
}
```

Two rules follow from the state having its own slot: `state` is already restored when `loadSnapshotParts` runs, so the parts hook may read it; and a part may itself be named `state` without colliding with the slot.

For both hook styles: on a restore the runtime first reconstructs the agent from its id (constructor parameters) and then calls your load hook, so keep the constructor free of side effects. Hooks run unpersisted and may be retried; a load hook that throws rejects the update. The runtime wraps your bytes in the principal-carrying envelope, so you never see it.

## Scaffolding

```bash
golem new --template kotlin/snapshotting --component-name example:counter --yes app
```

This scaffolds a ready-to-build agent using `Snapshotted<CounterState>` with `@Agent(snapshotting = "every(1)")`.

## Best Practices

1. **Keep state in one type** — with `Snapshotted<S>`, bundle all mutable state into a single `var state: S` (a `data class`) for clean persistence.
2. **Keep snapshots small** — large snapshots impact recovery and update time.
3. **Test round-trips** — verify that save → load produces equivalent state (mutate state, run a manual update, restart, assert the value survived).
4. **Handle migration** — when the state type changes between versions, ensure the new `S` (or your `loadSnapshot`) can decode snapshots produced by the old one (or accept a reset). The snapshot bytes are Kotlin-native; there is no cross-language snapshot migration. Use `CustomSnapshot` / `MultipartSnapshotted` when you need control over the format.
