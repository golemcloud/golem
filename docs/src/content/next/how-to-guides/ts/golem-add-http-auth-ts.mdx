# Enabling Authentication on TypeScript HTTP Endpoints

## Overview

Golem supports authentication on HTTP endpoints via OIDC providers. Authentication is enabled in the agent code and configured via security schemes in `golem.yaml`. See the [`golem-configure-api-domain`](/next/how-to-guides/common/golem-configure-api-domain) skill for details on setting up security schemes and domain deployments, including when to use `subdomain` versus `domain`.

## Enabling Auth on All Endpoints (Mount Level)

Set `auth: true` in the mount options of `http.mount(...)` to require authentication for all endpoints:

```typescript
import { z } from 'zod';
import { defineAgent, method, http } from '@golemcloud/golem-ts-sdk';

export const SecureAgent = defineAgent({
  name: 'SecureAgent',
  id: { name: z.string() },
  http: http.mount('/secure/{name}', { auth: true }),
  methods: {
    // All endpoints require authentication
  },
});
```

## Enabling Auth on Individual Endpoints

Set `auth: true` in the endpoint options (the second argument to a verb builder):

```typescript
export const ApiAgent = defineAgent({
  name: 'ApiAgent',
  id: { name: z.string() },
  http: http.mount('/api/{name}'),
  methods: {
    publicData: method({ input: {}, returns: z.string(), http: http.get('/public') }),
    privateData: method({ input: {}, returns: z.string(), http: http.get('/private', { auth: true }) }),
  },
});
```

## Overriding Mount-Level Auth

Per-endpoint `auth` overrides the mount-level setting:

```typescript
export const MostlySecureAgent = defineAgent({
  name: 'MostlySecureAgent',
  id: { name: z.string() },
  http: http.mount('/api/{name}', { auth: true }),
  methods: {
    // No auth required — overrides the mount default
    health: method({ input: {}, returns: z.string(), http: http.get('/health', { auth: false }) }),
    // Auth required (inherited from the mount)
    getData: method({ input: {}, returns: Data, http: http.get('/data') }),
  },
});
```

## Reading the Caller

When auth is enabled, a handler reads the signed-in user from its invocation context. The SDK passes the context as the second argument of every method handler, and as the `ctx` of `init`. `ctx.caller.original` is the principal that started the call chain: for a signed-in user it is a `user` principal, with the user's `claims`. `ctx.caller.immediate` is the principal that made this call. The context is not an input: it consumes no wire field and is **never** mapped to path/query/header variables.

```typescript
import { z } from 'zod';
import { defineAgent, method, http } from '@golemcloud/golem-ts-sdk';

export const ApiAgent = defineAgent({
  name: 'ApiAgent',
  id: { name: z.string() },
  http: http.mount('/api/{name}', { auth: true }),
  methods: {
    whoAmI: method({ input: {}, returns: z.object({ kind: z.string() }), http: http.get('/whoami') }),
    getData: method({ input: { id: z.string() }, returns: z.string(), http: http.get('/data/{id}') }),
  },
});

export const ApiAgentImpl = ApiAgent.implement({
  // Remember who created the agent. A PrincipalRef is data: it grants nothing by itself.
  init: (ctx) => ({ owner: ctx.caller.original.ref }),
  methods: {
    whoAmI(_input, ctx) {
      return { kind: ctx.caller.original.kind };
    },
    getData({ id }, ctx) {
      if (this.owner === undefined || !ctx.caller.original.equals(this.owner)) {
        throw new Error('Only the creator can read this data');
      }
      return `data for ${id}`;
    },
  },
});
```

The principal kinds are `user`, `account` (a Golem account, for example the CLI), `agent`, `tool` and `anonymous`; narrow with `kind`. A `Principal` or a `Caller` is a live value: it cannot be a method input, a result or part of a value type, and the build fails if a signature holds one. To store an identity, keep `ctx.caller.original.ref`, a `PrincipalRef`, and compare with `equals`; declare it in a schema with `s.principalRef()`. `this.getId()`, which returns the agent's `AgentId`, is also available on every handler's `this`.

## Deployment Configuration

After enabling `auth: true` in code, you must configure a security scheme in `golem.yaml`. See the [`golem-configure-api-domain`](/next/how-to-guides/common/golem-configure-api-domain) skill for the full details, including when to use `subdomain` versus `domain`. Quick reference:

```yaml
httpApi:
  deployments:
    local:
    - subdomain: my-app  # resolves to my-app.localhost:9006 by default
      agents:
        SecureAgent:
          securityScheme: my-oidc            # For production OIDC
        # or for development:
        # SecureAgent:
        #   testSessionHeaderName: X-Test-Auth
```
