# Calling Another Agent (Scala)

## Overview

Native definition-derived SDK clients extend `AgentCompanionBase`. CLI-generated internal bridge clients do not. The examples below use native SDK clients; no manually defined companion is required.

## Setup

Define the agent trait. The SDK auto-generates a `CounterAgentClient` companion object at build time:

```scala
import golem.BaseAgent
import golem.runtime.annotations.agentDefinition

import scala.concurrent.Future

@agentDefinition()
trait CounterAgent extends BaseAgent {
  class Id(val name: String)
  def increment(): Future[Int]
  def getCount(): Future[Int]
}
```

## Getting a Client

Use `CounterAgentClient.upsert(...)` with the target agent's constructor parameters:

```scala
val counter = CounterAgentClient.upsert("my-counter")
```

This returns a `CounterAgentRemote` with per-method wrapper fields for the **keyed** agent of these constructor parameters. The host creates the agent when it is missing; if it already exists, you get a handle to the existing instance. It throws `AgentRpcException` when the host rejects the client.

To create a new agent instead, use `CounterAgentClient.create(...)`, and to address an existing agent by its `golem.AgentId`, use `CounterAgentClient.getById(agentId)`. `create` returns a `Future` of the client; `getById` returns the client at once and throws `AgentRpcException` when no agent of this type has the ID. `counter.agentId()` returns the client's `Future[AgentId]`. See the [`golem-multi-instance-agent-scala`](/next/how-to-guides/scala/golem-multi-instance-agent-scala) guide.

## Awaited Call

Call a method and wait for the result:

```scala
val result: Future[Int] = counter.increment()
val count: Future[Int] = counter.getCount()
```

The call uses the asynchronous `invoke-and-await` host function under the hood — the calling agent **suspends** (yields the WASM event loop) until the target agent returns. The returned `Future` is genuinely async, enabling concurrent RPC calls to multiple agents.

## Ephemeral Targets

The signatures above describe durable targets with stream-free methods. Ephemeral clients, native and CLI-generated, expose only `upsert`. Their awaited calls return `Future[golem.runtime.rpc.InvocationResult[T]]`, which pairs the result with the invocation metadata of the one-shot instance that ran it.

An awaited call cannot be cancelled from Scala: a `Future` has no cancel. To cancel work before it starts, trigger or schedule it and cancel its handle.

Failures arrive as a failed `Future` with `golem.runtime.rpc.AgentRpcException`, whose `error: AgentRpcError` tells the cases apart: `Denied`, `NotFound`, `Cancelled`, `CannotCancelRunning`, `RemoteInternal`, `Conflict`, and the agent-domain errors.

## Other Call Modes

Each stream-free method also supports trigger and scheduling. Both return `Future[golem.runtime.rpc.Invocation[Out]]`, the handle of the accepted invocation, and never lend a scope card:

```scala
counter.increment.trigger()                             // returns once the target accepted it
counter.increment.scheduleAt(Datetime.afterSeconds(60)) // scheduled
```

The handle has `id`, `status()`, `awaitResult()` and `cancel()`. The ID is a locator, not authority: only the starter or a caller with the applicable management permission can observe or cancel the invocation. Dropping the handle only detaches, and a running invocation cannot be cancelled (`AgentRpcError.CannotCancelRunning`). See the [`golem-fire-and-forget-scala`](/next/how-to-guides/scala/golem-fire-and-forget-scala) and [`golem-schedule-future-call-scala`](/next/how-to-guides/scala/golem-schedule-future-call-scala) skills.

## Agents Without a Key

To create multiple distinct instances with the same constructor parameters, use `create` without `keyed`: each call makes a new agent with a new agent ID. See the [`golem-multi-instance-agent-scala`](/next/how-to-guides/scala/golem-multi-instance-agent-scala) guide.

## Cross-Component RPC

When calling agents defined in a **different component**, the generated client type is available after running `golem build` — the build step generates bridge SDK code for inter-component dependencies declared in `golem.yaml`.

## Avoiding Deadlocks

**Never create RPC cycles** where A awaits B and B awaits A — this deadlocks both agents. Use `.trigger()` (fire-and-forget) to break cycles. See the [`golem-fire-and-forget-scala`](/next/how-to-guides/scala/golem-fire-and-forget-scala) guide.
