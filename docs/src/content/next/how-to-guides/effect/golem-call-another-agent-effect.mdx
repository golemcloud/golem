# Calling Another Agent from an Effect Golem Agent

Every value returned by `defineAgent(...)` has a typed `client`. For durable targets, obtain a remote handle by yielding
`Target.client.upsert(id)`, then invoke one of its methods with the declared named-input
record. Both operations return Effects; do not translate Promise-based SDK examples or invent an
additional `.await()` call.

Ephemeral clients have only `upsert`; each call runs on a new one-shot instance. Their awaited
calls return `{ value, metadata }`, not the durable method's bare success value.

```typescript
const registerCount = (name: string, count: number) =>
  Effect.gen(function* () {
    const registry = yield* GlobalRegistry.client.upsert({});
    return yield* registry.register({ name, count });
  });
```

The function-call form of `register(...)` invokes the target and suspends the caller until the
typed result arrives. Agent handlers already receive the SDK's host services, so production handler
code does not provide a separate RPC `Layer`.

## Define and Address the Target

Define the target contract with `defineAgent`, `method`, and Effect Schema. The implemented value
retains the same typed `client` as the unimplemented agent spec.

```typescript
import { Effect, Ref, Schema } from "effect";
import { defineAgent, method, Snapshot } from "@golemcloud/effect-golem";

const RegistryEntry = Schema.Struct({
  name: Schema.String,
  count: Schema.Number,
});

const RegistryState = Schema.Record(Schema.String, RegistryEntry);
const RegistryEntries = Schema.Array(RegistryEntry);

export const GlobalRegistry = defineAgent({
  name: "GlobalRegistry",
  mode: "durable",
  id: {},
  snapshotting: Snapshot.define({
    schema: RegistryState,
    policy: Snapshot.policy.everyN(10),
  }),
  methods: {
    register: method({
      input: { name: Schema.String, count: Schema.Number },
      success: Schema.Boolean,
    }),
    getAll: method({
      input: {},
      success: RegistryEntries,
    }),
  },
}).implement({
  init: () => Ref.make<Record<string, typeof RegistryEntry.Type>>({}),
  methods: (state) => ({
      register: ({ name, count }) =>
        Ref.update(state, (entries) => ({
          ...entries,
          [name]: { name, count },
        })).pipe(Effect.as(count < 5)),

      getAll: () => Ref.get(state).pipe(Effect.map(Object.values)),
  }),
  snapshot: Snapshot.ref<Record<string, typeof RegistryEntry.Type>>(),
});
```

Constructor parameters and method parameters/results/errors must use WIT-representable schemas.
Automatic snapshot schemas are private JSON state and may additionally use JSON-representable
Effect schemas such as `Schema.Record(...)`. For a dynamic string-keyed snapshot collection, use a
record when keyed lookup is the natural state model; convert it to an array only at a public method
boundary whose WIT schema is `Schema.Array(...)`.

Constructor parameters form the key of the durable target instance. Pass the complete named
record to `client.upsert`:

```typescript
const getCounter = Effect.gen(function* () {
  return yield* CounterAgent.client.upsert({ name: "my-counter" });
});
```

For a singleton declared with `id: {}`, pass an empty record; `upsert()` and
`upsert(undefined)` are not the typed API:

```typescript
const getRegistry = Effect.gen(function* () {
  return yield* GlobalRegistry.client.upsert({});
});
```

`upsert` addresses the keyed agent of the agent id fields and creates it when it is missing, so
later calls with the same agent id fields address the same durable instance. To create a new agent
without a key instead, yield `Target.client.create(id)`; read its ID with `yield* remote.agentId`
and reconnect later with `Target.client.getById(agentId)`, which never creates an agent. See
[`golem-multi-instance-agent-effect`](/next/how-to-guides/effect/golem-multi-instance-agent-effect).

## Await a Remote Result in a Handler

Remote method inputs are always named records. Pass `{}` when the method declares `input: {}`.
Yield the remote call directly to use its success value:

```typescript
increment: () =>
  Effect.gen(function* () {
    const { count } = yield* Ref.updateAndGet(state, ({ count }) => ({
      count: count + 1,
    }));

    const registry = yield* GlobalRegistry.client.upsert({});
    return yield* registry.register({ name, count });
  }).pipe(Effect.scoped, Effect.orDie),
```

Here `increment` can declare `success: Schema.Boolean`: the returned boolean is the awaited result
of `register`. `Effect.scoped` owns the remote handle through the complete operation.
`Effect.orDie` removes typed client/transport failures from this public method's
error channel by converting them to defects. Use that only when an RPC infrastructure failure
should fail the invocation. If the caller should recover, use `Effect.catch` to return a fallback
or map the failure into a domain error declared by the caller method.

If the target method declares an `error` schema, that domain error is part of the remote call's
typed Effect error channel alongside RPC transport failures. Handle or map it deliberately; do not
use `try`/`catch` around an unexecuted Effect.

## Imports and Registration

- Import local modules with their emitted `.js` suffix under the generated NodeNext/ESM setup.
- Import the target's exported agent spec or implemented value to access `.client`.
- Ensure `src/main.ts` imports every implementation module for side-effect registration.
- For larger layouts, keep the `defineAgent(...)` spec in one module and call `.implement({ ... })` in
  a separate implementation module. Callers can then import the spec without registering another
  implementation.

## SDK Boundary

An agent ID in text form can be parsed once and bound to a typed definition:

```typescript
import { AgentId, Client } from "@golemcloud/effect-golem";

const bindCounter = (text: string) => Effect.gen(function* () {
  const id = yield* AgentId.parse(text);
  return yield* Client.bind(id, CounterAgent);
  // Equivalent: yield* CounterAgent.client.getById(id)
});
```

`Client.bind` reads the agent type of the ID from the host and connects through `getById`. It
rejects a full definition of another agent type, and binding an ID to an ephemeral definition,
with `ClientBindingError`. An unknown ID fails with an `RpcCallError` whose cause is `not-found`.
`AgentId.parse` checks only the UUID text form. Binding is not remote schema discovery and does not grant permissions: invocation
still requires host authorization. Handle parse, binding, and invocation errors deliberately.

For a separately deployed component, declare an agent dependency in the consuming component:

```yaml
components:
  my-app:consumer:
    dir: consumer
    templates: effect
    dependencies:
      agents:
        - my-app:provider/TsPeer
```

Run `golem build` to generate the Effect guest bridge, then import its exported class, for
example `import { TsPeer } from "ts-peer-guest-client"`. Unlike definition-owned clients, generated
guest bridges use positional arguments: `const peer = yield* TsPeer.upsert("peer")`, then, for
example, `yield* peer.echo("hello")`. A durable bridge also has `create(..., { keyed, config, env })`
and `getById(agentId)`; an ephemeral one has only `upsert`. These calls return Effects, not
Promises. Read the generated declarations for the exact constructor, method, and configuration
shapes; do not edit generated files.
This guest bridge is distinct from the external REST bridge used by Node.js applications.

Avoid awaited RPC cycles such as A waiting for B while B waits for A; sequential durable agents can
deadlock. Use the real remote method's `.trigger(input)` form only when fire-and-forget semantics are
acceptable and the result is not needed.
