# Core concepts

A Golem application combines agents, the tools they call, and the artifacts they serve on one runtime. A quarterly report request shows how the pieces work together.

## Follow one request

A signed-in user asks for a quarterly report.

1. **The request is authenticated.** The HTTP endpoint requires a login; Golem rejects callers without a valid token before any agent runs.
2. **The request reaches a named agent.** The endpoint maps the path to `ReportAgent("acme", "q3")`, which Golem creates on first use. Later calls with the same parameters reach the same agent.
3. **The agent calls a model and tools.** Its harness calls the model provider and runs tools such as `web-fetch` and `write-file`. The host checks the agent's cards before each gated effect and records each call and result in the oplog.
4. **The agent waits for approval.** It awaits a promise. After a short idle threshold, Golem unloads the waiting agent from memory. The wait survives redeploys.
5. **The agent delivers the report.** It writes the report to its filesystem, serves it over HTTP, and streams progress over a Durable Stream that a reloaded browser resumes.

If the node fails at any step, Golem rebuilds the agent from its oplog. Completed model calls are recovered from the oplog rather than requested again. Every tool call executes exactly once.

## Terms used across these pages

| Term | Definition |
|---|---|
| Agent type | Code that defines an agent's constructor parameters, state, and methods. |
| Agent | An instance of an agent type, identified by type and constructor parameters within an environment. |
| Component | The WebAssembly unit you build and deploy; it contains one or more agent types. |
| Application | Components plus the `golem.yaml` manifest, which configures everything else, including environments. |
| Environment | A deployment target such as `local` or `prod`, with its own agents, secrets, and storage. |
| Oplog | A durable agent's append-only journal of its execution, including invocations and durable host calls with their results. |
| Card | An unforgeable handle carrying grants; an agent's cards form its wallet. |
| Artifact | What an agent delivers: an HTTP endpoint, web page, file, or stream. |

## Keep these distinctions clear

**Identity is not authority.** `ReportAgent("acme", "q3")` names an agent. The caller's login identifies the user, and the agent's cards decide what the agent may do.

**The oplog makes an agent durable.** Snapshots are optional and only shorten recovery.

**Tools run through the runtime.** A component tool such as `bash` or `npm` runs in a fresh WebAssembly instance, not as a host process. See [Tools](/next/concepts/tools).
