# Invoke through the REST API

The Golem REST API invokes an agent method with one endpoint. See the [Agent REST API reference](/next/rest-api/agent) for every field.
The endpoint is a direct, low-level API: arguments and results travel in the REST wire form described below. To expose agents to the world, define [custom HTTP APIs](/next/invoke/making-custom-apis), or call them from a program through a [bridge library](/next/invoke/bridge-libraries), which builds these requests for you.

## Invoke an agent

```
POST /v1/agents/invoke-agent
```

The request body selects the agent by its application, environment, agent type and constructor parameters, and names the method to call:

```json
{
  "appName": "my-app",
  "envName": "local",
  "agentTypeName": "CounterAgent",
  "parameters": {"kind": "record", "value": {"fields": [{"kind": "string", "value": "my-counter"}]}},
  "methodName": "increment",
  "methodParameters": {"kind": "record", "value": {"fields": [{"kind": "u32", "value": 5}]}},
  "mode": "await"
}
```

- `parameters` are the constructor parameters and `methodParameters` the method parameters, each a record of the parameter values in declaration order.
- `mode` is `await` to wait for the method to finish, or `schedule` to enqueue the invocation and return at once. With `schedule`, `scheduleAt` (an RFC 3339 date-time) delays the invocation.
- `idempotencyKey` (or the `Idempotency-Key` header) identifies the invocation. Golem runs an invocation with the same key once. Without a key, Golem generates one.
- `phantomId` selects a phantom agent instance, and `config` overrides local agent configuration.

The response carries the `agentId`, the `idempotencyKey` and, for `await`, the `result`: the method's result together with its schema graph.

## Implicit agent creation

If the agent does not exist, the invocation creates it.

## Cancel a pending invocation

Golem runs the invocations of one agent in sequence, so an invocation that has not started yet can be cancelled, identified by its idempotency key:

```
DELETE /v1/components/{component_id}/workers/{agent_name}/invocations/{idempotency_key}
```

## The REST wire form

Every value is a JSON object with a `kind` and a `value`:

| Kind | Example |
|------|---------|
| `bool`, `u8` … `u32`, `s8` … `s32`, `f32`, `f64` | `{"kind": "u32", "value": 5}` |
| `u64`, `s64` | `{"kind": "s64", "value": "9007199254740993"}` (a string, so no precision is lost) |
| NaN and the infinities | `{"kind": "f64", "value": {"$float": "nan"}}`, with `positive-infinity` and `negative-infinity` |
| `string` | `{"kind": "string", "value": "Golem"}` |
| `record` | `{"kind": "record", "value": {"fields": [{"kind": "u8", "value": 1}, {"kind": "string", "value": "x"}]}}` |
| `variant` | `{"kind": "variant", "value": {"case": 2, "payload": {"kind": "string", "value": "payload"}}}` |
| `map` | `{"kind": "map", "value": {"entries": [[{"kind": "string", "value": "key"}, {"kind": "u8", "value": 1}]]}}` |
| `result` | `{"kind": "result", "value": {"tag": "err", "value": {"kind": "string", "value": "failed"}}}` |

<Callout type="info">
    The file `test-data/rest-wire-form/v1.json` in the Golem repository lists a wire-form example of every kind, and the values that must be rejected.
</Callout>

The value alone does not say which schema it follows: the agent type's metadata does. Read the agent type with `golem agent-type get`, or through the REST API, to get the parameter and result schemas of its methods.
