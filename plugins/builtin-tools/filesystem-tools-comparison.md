# Filesystem tool implementation comparison

This report compares the Rust and MoonBit implementations of `read-file`, `write-file`, and
`edit-file`. Both components were built through the Golem CLI from the same full `agent-guest`
world and expose the same five interfaces and 27 core exports (25 functions plus `memory` and
`_start`).

## Component size

| Implementation | Component | Stripped component | Core code | Core data |
| --- | ---: | ---: | ---: | ---: |
| Rust | 1,233,592 B | 1,219,887 B | — | — |
| MoonBit | 1,080,792 B | 1,070,119 B | 905,347 B | 94,348 B |

Under the same full ABI, MoonBit is 152,800 B (12.4%) smaller than Rust before stripping and
149,768 B (12.3%) smaller after stripping.

Shared cross-interface MoonBit canonical-ABI lift/lower helpers reduced the MoonBit component from
1,242,039 B to 1,080,792 B, a 161,247 B (13.0%) reduction. The stripped component fell by the same
161,247 B, from 1,231,366 B to 1,070,119 B. The generated core code fell from 1,066,490 B to
905,347 B. The helper sharing is automatic and does not require a generator flag.

The older 1,040,266 B MoonBit artifact is not a like-for-like baseline: it used a smaller,
incompatible ABI with four interfaces and 21 exports and omitted the middleware guest interface.
The final full-ABI component is only 40,526 B larger while carrying five interfaces and 27 exports.

The full world still requires callable agent, tool, middleware, and snapshot ABI wrappers even when
a component registers no implementation for a capability. Capability-sensitive export roots let
the linker remove absent SDK runtimes; shared generator helpers remove duplicate canonical-ABI
machinery across those mandatory interfaces. In the empty fixture this reduced generated export
code from approximately 536 KiB to 399 KiB and middleware ABI attribution from approximately
271 KiB to 147 KiB. The remaining wrappers are part of the unchanged external WIT contract, not a
retained middleware implementation.

## Worker-executor performance

The benchmark invokes the committed release components through the in-process worker executor on
an optimized host binary. Each operation uses a 64 KiB file. Each implementation gets a separate
worker and deployment, 10 warm-up rounds, and then 100 measured invocations per operation. Edit
setup writes are excluded from the edit samples. The measurements include dispatch, component
execution, and sandbox filesystem overhead; they are not isolated guest-runtime timings.

The following three uncontended runs were performed after replacing MoonBit's 64-byte stream chunks
with bounded 64 KiB batching. The final run invoked the already-linked test executable directly, so
it performed no compilation. Values are medians, with p95 in parentheses.

| Operation | Rust run 1 | Rust run 2 | Rust final | MoonBit run 1 | MoonBit run 2 | MoonBit final |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Write 64 KiB | 4.935 ms (5.700) | 5.628 ms (6.441) | 4.854 ms (5.172) | 5.634 ms (6.529) | 6.095 ms (7.249) | 5.520 ms (6.492) |
| Read 64 KiB | 5.075 ms (6.035) | 5.594 ms (7.661) | 5.102 ms (5.994) | 5.604 ms (6.346) | 6.190 ms (6.784) | 5.488 ms (7.210) |
| Edit 64 KiB | 6.399 ms (7.539) | 7.073 ms (7.770) | 6.516 ms (8.125) | 6.787 ms (7.527) | 7.569 ms (8.515) | 6.816 ms (8.260) |

The final paired medians put MoonBit 0.666 ms behind on write, 0.386 ms behind on read, and 0.300 ms
behind on edit. This replaces the earlier approximately 40 ms MoonBit write/edit result,
which was caused by 1,024 64-byte canonical stream writes per 64 KiB payload. Generated byte
streams and the handwritten tool stdout adapter now use a bounded 65,536-byte window. Boundary
tests cover arrays and byte views, partial acceptance, blocked drains, cancellation, peer drop, and
failure cleanup.

The final cold-write samples were 22.176 ms for Rust and 19.797 ms for MoonBit. A single cold sample
per run is diagnostic only and is not sufficient for a cold-start performance claim.

## Verification

- Both filesystem components pass `wasm-tools validate` and expose the same full ABI.
- Direct Rust/MoonBit behavior parity passed on the worker executor.
- Guest-invoked filesystem behavior passed on the worker executor.
- The benchmark exercises real worker-executor tool deployment and invocation, not host mocks.
- MoonBit SDK regeneration is deterministic and contains no hand edits to generated bindings.

The size measurements do not include optional Binaryen rewriting. Rust release symbol stripping is
enabled, while restricted `wasm-opt -Oz` remains an explicitly measured opt-in rather than a
deployment default.
