# In-process JavaScript guest tests

The `golem-js-guest-tests` crate's `js-guest` binary injects these bundles into the real TypeScript
and Effect `agent_guest.wasm` templates and preinitializes them with the same
optimizer options as `golem build`. It then calls the guest's discovery export
through the shared component metadata extractor. It starts no external processes.

Each smoke module computes an asymmetric arithmetic result and captures the clock
in its agent description during module initialization. Discovery must return that
description after preinitialization, including the build-time clock value of zero.
Skipping preinitialization would capture the discovery host's current clock instead.

The arithmetic is only a recognizable module-initialized value, not an arithmetic
conformance test. These smoke tests prove that the real SDK bundles can be injected,
preinitialized and discovered with their initialized state intact. They do not call
the agent's `get` method or test worker execution, awaited I/O or error remapping.
The maps are checked for reproducible generation, not diagnostic accuracy.

This is a test-only workspace crate. Its dependencies are the shared component
metadata extractor, the JS injection/optimization library and test utilities. It
does not depend on `golem-cli`, the worker executor or service test infrastructure.

## Build prerequisites and run

Install the repository's Rust and JS toolchains, including the pinned
`wasm-rquickjs-cli`, Node 24, pnpm and WASI SDK. Build both SDK templates from the
same checkout before running the Rust tests:

```shell
# From sdks/ts:
pnpm install --frozen-lockfile
pnpm --filter @golemcloud/golem-ts-sdk run build
pnpm run build-agent-template

# From sdks/effect:
npm ci
npm run build-agent-template

# From the repository root:
cargo make js-guest-tests
```

For a direct run, use
`cargo test -p golem-js-guest-tests --test js-guest -- --test-threads=1 --report-time`.
Missing or empty templates fail; the tests never skip a guest. The task does not
build templates automatically, so it also works with CI's prebuilt artifacts.
It accepts the existing `TEST_R_BUILD_OPTS` and report options for prebuilt native
test binaries. The ordinary `unit-tests` task runs library tests only and does not
execute this target.

## Regenerate and check bundles

The sources live in the SDK suites:

- TS: `sdks/ts/packages/golem-ts-sdk/tests/components/js-guest-smoke.ts`, bundled by
  `tests/component-bundle.test.mjs`.
- Effect: `sdks/effect/test/fixtures/capabilities/js-guest-smoke.ts`, bundled by
  `test/component-build.test.ts`.

The suites use their component plugins and the shared
`sdks/javascript/js-bundle-fixtures.mjs` writer. The generated bundles keep real
host imports external; they do not contain Vitest host fakes. Source maps use
relative paths and are checked along with the bundles. Install both SDKs' JS
dependencies before using these root tasks:

```shell
cargo make generate-js-bundle-fixtures
cargo make check-js-bundle-fixtures
```

The generation task explicitly sets `GOLEM_UPDATE_JS_BUNDLES=1`. Ordinary SDK test
runs compare generated bytes to the committed files and reject stale, missing or
extra files. Never set the update variable in CI. Commit source changes and the
regenerated files together. Later tests can add bundles to the same per-SDK file
set; do not run Rollup, Node or another tool from a Rust test.

## CI ownership

Main validation runs `main-validation-js-guests` after TS and Effect SDK validation,
using fresh local templates and the general native producer's binaries metadata.
The task is visible in prepare progress and contributes failures and CTRF reports
to the exact-source validation result.

There is no separate GitHub Actions job for this tier. CI execution belongs to
Main validation; SDK validation performs the bundle drift checks through Vitest.

CLI orchestration assertions belong in the CLI integration suite. Post-snapshot
worker behavior belongs in worker-executor tests; runtime semantics belong in
wasm-rquickjs. This suite covers real-guest injection and preinitialization without
starting a CLI or server.
